# Feature compositions

The screens of the product, composed from `@ledger/design-system` parts over the domain modules in `src/lib`. Each file here is one feature composition or the shared adapter several of them use. This map says what each one is and which files are the references named by [the product pattern contract](../../../docs/guides/product-patterns.md); read that contract before changing a screen, and copy its reference for the shape you are building rather than the nearest neighbour.

The wizard, the pickers shared with the inspector, the confirmation dialog (whose `action` runs a destructive command inside the prompt), the draft guard and the shell live in `src/components/app`, with the generic create and edit form every record without a dedicated dialog uses (`record-editor.tsx`, reached through `product-record-dialog.tsx`), the evidence file's upload, download and recovery (`evidence-file.tsx`: a DropZone, then an Attachment row), the field wrappers every form uses (`fields.tsx`, `element-fields.tsx`), the submit feedback behind them (`form-feedback.ts`) and the status components bound to the one status map in `src/lib/status.ts` (`status.tsx`). Routes in `src/routes` assemble these compositions and set the browser title; a route holds no domain logic of its own.
