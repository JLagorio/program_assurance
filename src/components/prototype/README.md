# Feature compositions

The screens of the product, composed from `@ledger/design-system` parts over the domain modules in `src/lib`. Each file here is one feature composition or the shared adapter several of them use. This map says what each one is and which files are the references named by [the product pattern contract](../../../docs/guides/product-patterns.md); read that contract before changing a screen, and copy its reference for the shape you are building rather than the nearest neighbour.

## Shared adapters and hosts

| File                                                       | Role                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `product-collection.tsx`                                   | **Reference: register adapter.** Every product collection composes it: toolbar, query recovery, responsive table and empty region. Domain adapters keep their typed columns.                                                                                                                                                                                                                     |
| `record-preview.tsx`                                       | **Reference: preview host.** `RecordPreviewProvider` owns one `Shell.Panel` across registers and returns focus to a nested frame's opener on Back; `RecordPreviewPanel` and `RecordPreviewActions` supply the outer navigation and inner record header; `RecordLink` renders a name as a router `TextLink`; `useRemovalFocus` moves focus to the collection's primary after a confirmed removal. |
| `record-trail.tsx`                                         | `RecordTrail` and `TrailLink`: a record page's breadcrumb, matched exactly so only the current page is announced as current.                                                                                                                                                                                                                                                                     |
| `record-summary-preview.tsx`                               | A generic preview for collections without a domain-specific one: it requires the `fields` the reader asks for, draws each by its kind (a vocabulary, a date, a related record's name) or a column's `value` and `statuses`, and takes a `title` for a model with no name of its own.                                                                                                             |
| `record-tools.tsx`                                         | The schema-record register on `DataTable`: kinds decided by key, the two empties. Used by the inspector routes.                                                                                                                                                                                                                                                                                  |
| `work-common.tsx`                                          | **Reference: states.** `QueryState` (skeleton lines while loading, one Alert with Retry for a failure, stale content kept after a failed refresh, the recovery announced), `DetailFacts` (a KeyValue.Group that widens long labels), `MissingRecord` (also `inline` in a tab or frame) and `VersionName`. Its value-only `StatusBadge` is a deprecated shim over `@/components/app/status`.      |
| `work-format.ts`, `library-utils.ts`, `assessment-tabs.ts` | Formatting, download and tab helpers. No rendering.                                                                                                                                                                                                                                                                                                                                              |
| `use-system-assurance.ts`                                  | The one projection every system surface reads: tree, preview and record.                                                                                                                                                                                                                                                                                                                         |

## Forms and pickers

| File                                 | Operation                                                                                                                                                                                                                                                  |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create-task-dialog.tsx`             | **Reference: create form.** Create task: the Dialog whose trigger, title and primary agree; Fields with a FieldError each, an ErrorSummary when several fail, `DialogBody`, the Dialog's `pending` lock with `useDraftGuard`, and an Alert for the result. |
| `create-evidence-dialog.tsx`         | Create evidence artifact, on the reference form's shape.                                                                                                                                                                                                   |
| `add-requirement-details-dialog.tsx` | Add authored content to a requirement.                                                                                                                                                                                                                     |
| `add-from-library.tsx`               | Add from library: the `PickerSheet` with the target × claim matrix.                                                                                                                                                                                        |
| `add-product-system.tsx`             | Add system from product: pick a published version and configuration, then name and categorize the variant, with Back to the choice.                                                                                                                        |

The wizard, the pickers shared with the inspector, the confirmation dialog (whose `action` runs a destructive command inside the prompt), the draft guard and the shell live in `src/components/app`, with the generic create and edit form every record without a dedicated dialog uses (`record-editor.tsx`, reached through `product-record-dialog.tsx`), the evidence file's upload, download and recovery (`evidence-file.tsx`: a DropZone, then an Attachment row), the field wrappers every form uses (`fields.tsx`, `element-fields.tsx`), the submit feedback behind them (`form-feedback.ts`) and the status components bound to the one status map in `src/lib/status.ts` (`status.tsx`). Routes in `src/routes` assemble these compositions and set the browser title; a route holds no domain logic of its own.
