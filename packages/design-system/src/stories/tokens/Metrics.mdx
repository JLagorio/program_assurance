# Metrics

Dimension is this system's own tier. Control heights are a themed axis rather than each component's own, so a control, a row, an icon and a layout region each have a token. The motion tokens share this sheet and have their own page (Tokens/Motion); the icons have theirs (Tokens/Icons).

## Controls

| Token                      | Value | Utility                                   | Use                                                    |
| -------------------------- | ----- | ----------------------------------------- | ------------------------------------------------------ |
| `dimension.control.xsmall` | 24px  | `h-control-xsmall`, `size-control-xsmall` | Button xsmall, the densest chrome.                     |
| `dimension.control.small`  | 28px  | `h-control-small`, `size-control-small`   | Button small, chips, menu items, side nav items.       |
| `dimension.control.medium` | 32px  | `h-control-medium`, `size-control-medium` | The default: Button, Input, Select, Combobox triggers. |

## Parts

A part's own size: a popup's width, a menu's narrowest, a placeholder's size. Each is read by its part through `token()` in the part's style, so it has no class. A product sizes a part through the part's props, or `style` where the part's page says so, and never picks one of these for its value: the popover's 288px is also the `@2xs` container size, but it changes with the popover, not with the container query.

| Token                           | Value  | Part                   | Use                                                                                  |
| ------------------------------- | ------ | ---------------------- | ------------------------------------------------------------------------------------ |
| `dimension.part.tooltip`        | 320px  | Tooltip                | The widest it grows, within the room the window leaves.                              |
| `dimension.part.hoverCard`      | 256px  | HoverCard              | Its width, within the room the window leaves.                                        |
| `dimension.part.popover`        | 288px  | Popover                | Its width, within the room the window leaves.                                        |
| `dimension.part.command`        | 560px  | CommandDialog          | The widest it grows.                                                                 |
| `dimension.part.menu`           | 128px  | DropdownMenu           | Its narrowest, unless the trigger is wider.                                          |

## Breakpoints

| Token                        | Value  | Variant  | Use                                                                              |
| ---------------------------- | ------ | -------- | -------------------------------------------------------------------------------- |
| `dimension.breakpoint.sm`    | 40rem  | `sm:`    | Tailwind's sm. Pagination's words, Stat's columns and a two-month Calendar from here. |
| `dimension.breakpoint.md`    | 48rem  | `md:`    | Tailwind's md. `TopNav.End` shows its `overflow` menu below it.                   |
| `dimension.breakpoint.lg`    | 64rem  | `lg:`    | Tailwind's lg. The side nav is inline from here and an overlay below.            |
| `dimension.breakpoint.aside` | 75rem  | `aside:` | The aside sits beside Main from here while no panel is open.                     |
| `dimension.breakpoint.panel` | 80rem  | `panel:` | The panel is a full-height column beside the page; below, it replaces Main.      |
| `dimension.breakpoint.wide`  | 110rem | `wide:`  | The aside sits beside Main even while a panel is open.                           |
| `dimension.breakpoint.xl`    | 80rem  | `xl:`    | Tailwind's xl, the panel breakpoint under its Tailwind name for Grid's `xl` count. |

One source for three readers: `layout.css` writes `@media (width >= theme(--breakpoint-panel))`, the shell reads `tokenValue("dimension.breakpoint.panel")` for `matchMedia`, and a class takes the variant. `sm`, `md`, `lg` and `xl` restate Tailwind's values so a class and a media query cannot drift apart. Where `reset.css` is imported, it clears Tailwind's own breakpoints first, so these seven are the only ones: `2xl:` (Tailwind's 96rem) does not exist.

## Container sizes

A part inside a panel, a rail, a card or a dialog switches on its own width, not the window's, through a container query. These are the sizes it reads: the `--container-*` theme keys, one token each. Tailwind's scale is restated at its own values, so every `@md:` and `@3xl:` class keeps its width and now reads a token, and the kit adds two of its own. Where `reset.css` is imported, it clears Tailwind's own copies first, so a container size the tokens do not name does not exist.

The names are Tailwind's, and they are not the breakpoints: `@md` is 28rem, the width of a container, while `md:` is the 48rem viewport. Name a container on the part (`@container/field-group`) and query it by name (`@md/field-group:`) so a nested container cannot answer instead.

| Token                              | Value                | Variant            | Where it switches                                                                       |
| ---------------------------------- | -------------------- | ------------------ | --------------------------------------------------------------------------------------- |
| `dimension.container.3xs`          | 16rem                | `@3xs:`            | A card header puts its actions beside the title; an input group shows its shortcut.     |
| `dimension.container.2xs`          | 18rem                | `@2xs:`            | No part yet.                                                                            |
| `dimension.container.xs`           | 20rem                | `@xs:`             | No part yet.                                                                            |
| `dimension.container.sm`           | 24rem                | `@sm:`             | Pagination shows its Previous and Next words.                                           |
| `dimension.container.compact`      | 25rem                | `@compact:`        | Below it a region is compact: the panel header gives its actions a row under the title. |
| `dimension.container.md`           | 28rem                | `@md:`             | A field group sets label and control side by side.                                      |
| `dimension.container.lg`           | 32rem                | `@lg:`             | No part yet.                                                                            |
| `dimension.container.xl`           | 36rem                | `@xl:`             | Below it a side-by-side Diff stacks its halves and reads as the inline view.            |
| `dimension.container.2xl`          | 42rem                | `@2xl:`            | No part yet.                                                                            |
| `dimension.container.3xl`          | 48rem                | `@3xl:`            | A WorkPane sets its list beside the detail; the top nav shows its search as a field.    |
| `dimension.container.split`        | 50rem                | `@split:`          | Two panes side by side; below it RecordBrowser's open preview replaces the list.        |
| `dimension.container.4xl` to `7xl` | 56, 64, 72 and 80rem | `@4xl:` to `@7xl:` | No part yet.                                                                            |

In a stylesheet, a container query reads the same key: `layout.css` writes `@container (width < theme(--container-split))`, and Tailwind writes the value in, since a query cannot read a custom property. A new switch uses one of these sizes; when none fits, the size is a new token with a description of what switches there, never a literal in a query.

`src/styles/layout.css` adds the few templates a class string cannot say, each reading these tokens: `grid-cols-list-detail`, `sticky-rail`, `min-h-work` and `fill-window`, and `shell.css` adds `shell-root`, the navigation grid. A record page's main column and rail are the Shell's Main and Aside, not a grid template. The shell sets `--shell-top` (banner plus top nav) so a sticky rail knows where to stop, and its main area sets `--shell-inset-bottom` so a filled register knows where to end. A rail in a scroller of its own reads `--rail-top` and `--rail-max-height` instead; a WorkPane in a dialog's body or a panel sets them to that scroller's top and height.
