# PageSkeleton

**Status: Stable.**

What a screen looks like before its data arrives, in the shape of the page that is coming, drawn from the [Skeleton](?path=/docs/components-skeleton--docs)'s shapes so the real page lands on the same lines. The router shows it while a route is pending. A page loads progressively: a section that loads on its own draws its own Skeleton inside a page that has already landed.

<Canvas of={Stories.PageSkeletonMatrix} />

## Anatomy

| Variant    | Parts                                                                                                                                                                                                                                                                 |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `register` | A heading shape where the PageHeader's title will be, nothing under it; the toolbar's row at `dimension.control.medium` (the search, two filters, the primary at the end); the table's header row and `rows` rows at the row heights DataTable's loading state keeps. |
| `record`   | A line for the trail; the title with an action at the end of its row; a tab strip over a rule; two sections at the reading measure. The Details rail is the shell's Aside, which arrives with the page.                                                               |

## Variants

- **`register`**, the default, for a collection page and for a route the router knows nothing about.
- **`record`**, for a record route: pass `<PageSkeleton variant="record" />` as its pending component.

<Canvas of={Stories.Register} />
<Canvas of={Stories.Record} />

Not built, and why: a dashboard shape, because a dashboard's widgets load on their own and each draws its own Skeleton; per-section skeletons, because those are the sections' own, drawn from Skeleton where they load.

## Sizes

`rows` sets how many table rows a register draws, 8 by default, about a screen. The skeleton is as wide as the page, and its lines follow the page's width below their own.

<Canvas of={Stories.Narrow} />

## States

One state: waiting. It says what it is waiting for once, and the shapes stay until the page replaces it.

## Modifiers

- **`variant`** as in Variants.
- **`rows`** as in Sizes.
- **`label`**: what the wait is, "Loading page" by default (the `loadingPage` message). Name the page when the route knows it: "Loading risks".

## Content

- **The shape of the page that is coming.** A register has no sentence or tabs under its title; a record has a trail, actions and tabs. The swap to the real page moves nothing.
- **Shown after a short delay.** Give the router a pending delay (about 150ms) and a minimum time on screen, so a fast route never flashes it.
- **Never beside content.** It replaces the page; a section that loads later draws its own.

## Style

| Element  | Token                                                                               |
| -------- | ----------------------------------------------------------------------------------- |
| Title    | Skeleton heading, at most 240px (register) or 320px (record)                        |
| Toolbar  | `dimension.control.medium` high · `space.100` between · `space.200` above the table |
| Rows     | `dimension.row.header`, then `dimension.row` each · `color.border` under every row  |
| Tabs     | three Skeleton lines · `space.250` apart · `color.border` rule · `space.150` under  |
| Sections | a line, then three lines · `space.150` between · at `dimension.layout.measure`      |
| Layout   | `space.300` between the parts                                                       |

## Accessibility

- **Said once.** On mount it sends its `label` to the kit's persistent polite live region (`announce`), which a screen reader has registered before the message arrives; a status region inserted with its words already in it is heard by almost none. Several skeletons that appear together are said once.
- **Found by browsing.** The root is a `role="status"` holding the same words as visually hidden text, so a reader who moves through the page meets them.
- **The shapes are hidden** from assistive technology; the words carry the meaning.
- **Forced colours** draw every shape in `GrayText`, so the page is never blank.
- **Reduced motion stops the pulse**; the shapes stay.

## Don't
