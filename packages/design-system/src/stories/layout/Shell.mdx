# Shell

The persistent application frame, inspired by [Atlassian's navigation layout](https://atlassian.design/components/navigation-system/layout/). It owns navigation, page gutters, responsive placement and panel scrolling. Product code supplies navigation links and route content.

<Canvas of={Stories.ComposedPanel} />

Mount Shell once in a shared router layout. Place Banner, TopNav, SideNav and Main there. Child routes render Shell.Aside or Shell.Panel to contribute to the frame's stable region slots. Contributions preserve route React context and disappear when their route unmounts. They mount on the client after slot destinations exist.

Every part renders one element and forwards its native props and its ref to it; AppLogo, Profile, SideNav.Item and Panel.Title take Base UI `render` where the element may change, so Profile is a menu's trigger through `render` and a side nav item is a router link. The SideNav.ToggleButton is a child of TopNav.Start and places itself; TopNav.End is a named group that renders its children as given, and a product that needs them to fold on a phone renders its own menu there.

Aside contains supporting context. Panel contains dismissible selected-record or task content. With `title` (and `actions`) it renders its built-in header, close and resizer; without them compose Panel.Header, Panel.Title, Panel.Actions, Panel.Close, Panel.Body and Panel.Splitter yourself, as Composed panel shows, to change the heading's level, the labels or the padding. Panel.onClose is required either way and the Title names the landmark. From the `panel` breakpoint (`dimension.breakpoint.panel`, 80rem: 1280px at the default root size; see [Metrics](?path=/docs/tokens-metrics--docs)) the panel is the last column for the whole height of the window: the banner and the top nav stop at its edge, so opening it narrows everything and covers nothing. Below it the panel replaces the visible Main area under the top nav while retaining Main's state, and it returns focus on close. Global navigation remains available; use Sheet for modal work.

Every default name (Banner, Top navigation, Side navigation, Main content, Page context, Details, Actions, Switch product, the toggle's two labels, the splitters' and the skip links') is a locale message, so a product translates them once with `LedgerLocaleProvider`; a `label` prop overrides one instance. The splitters take the arrow keys, Home for the minimum and End for the maximum. Left and Right move the handle in that physical direction, including right-to-left layouts. Restored widths retain the reader’s desktop preference: the current desktop layout is capped at half the viewport, and opening the shell on a phone does not overwrite that preference. Navigation still uses its 90vw overlay limit on phones.

SideNav retains its existing collapse, persistence, keyboard and resize behavior. Main uses document scrolling; Panel scrolls inside the available viewport. A register that is the page fills the rest of the window with DataTable `fill`: Main publishes its bottom inset as `--shell-inset-bottom`, and the layout otherwise owns placement, so content patterns do not add sticky rails or nested page frames.

Set `collapsedSideNav="icons"` on Shell to keep a 56px navigation rail when collapsed on desktop. The default, `"hidden"`, hides the side nav and retains the hover flyout. Supply meaningful icons for top-level items and expandable groups. In icon mode, destination names remain accessible and appear in tooltips on hover or focus; the active destination and profile avatar remain visible. Section headings and nested destinations are visually hidden. Custom SideNav.Header content, such as navigation search, is hidden in the rail and returns when expanded. Activating an expandable group expands the shell and opens that group. Hovering the toggle does not open a flyout in this mode. With the default app mark, the collapsed expand control occupies the mark’s existing position and appears on hover or keyboard focus. The mark is visible at rest, and the product name keeps its position through collapse and expansion. Phone navigation keeps its separate visible toggle. The splitter returns with the remembered width when expanded, and phone navigation continues to use the existing overlay. `shellScript` and `shellScriptFor` preserve the compact rail before hydration when collapse state is stored. See [Icon rail](?path=/story/layout-shell-icon-rail--desktop) for keyboard, RTL, phone and first-paint examples.

`Shell.Panel.actions` places route-owned controls immediately before Close in the built-in header. Collection previews compose `Panel.Header`, `Panel.Actions` and `Panel.Close` for a navigation-only outer bar: previous/next through the displayed rows, a native full-record link and, for nested frames, Back. Put the visible record name and domain commands in a `PageHeader` at the beginning of `Panel.Body`, using an h2 and `PageHeader.Actions`. Give the panel an accessible `label` when its outer bar has no `Panel.Title`. The route owns row order, destinations and endpoint availability; Shell only supplies placement. The Record header narrow story exercises both headers at the minimum panel width.

See [page composition](?path=/docs/layout-pages--docs) for route and tab examples.

### The end slot on a phone

`TopNav.End` never shrinks, so what it holds decides the top nav's width. Give it `overflow`, one menu holding the same commands, and below the `md` breakpoint the menu stands in for the children (the Record rail at 390px story). Without it, keep the end items few enough for the narrowest window the product serves.

### Narrow panel headers

Panel header slots respond to the panel container, including a manually resized desktop panel. Below 400px, a title with actions occupies a full row and navigation/Close share the row beneath; title-only headers keep Close beside the title. A PageHeader inside the panel follows its own rule: its actions take the row under the title when the row cannot hold the title's measure beside them. The normal desktop header remains one row. See the 240px, 320px and 640px Panel header stories, composed-slot forwarding and Panel record header examples.
