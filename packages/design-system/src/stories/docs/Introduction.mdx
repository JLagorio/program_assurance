# Ledger

Ledger is the design system behind the programme assurance product: one set of decisions about colour, type, space, shape, motion and behaviour, shipped as a package that any React and Tailwind project can install.

It is built on three ideas.

**Every design value is a token.** A colour is `color.text.subtle`, not a hex code and not a Tailwind grey. A space is `space.200`, not `16px`. A control is `dimension.control.medium` tall. Tokens are named for their role, so a screen reads as intent and the visual DNA lives in one place. Change a token and every screen follows; add a colour mode and no component changes.

**States are tokens too.** Hovered, pressed, selected and disabled are their own tokens, never alpha on a base colour. That is what makes dark mode a mechanical flip instead of a redesign, and it is the rule the lint enforces most strictly.

**Layout goes through primitives.** Box, Stack, Inline, Flex and Grid take token-typed props. Product code says `<Stack space="space.200">` and never writes a margin.

## Where things are

- **Guidance** is where to start: [Getting started](?path=/docs/guidance-getting-started--docs) installs the package and mounts its providers, [Choosing a part](?path=/docs/guidance-choosing-a-part--docs) finds the part for a need, [Recipes](?path=/docs/guidance-recipes--docs) shows how parts compose into a register, a record, a preview and a form, and [Which token](?path=/docs/guidance-which-token--docs) gives the short answer by job. The grammar, the lint rules, story conventions and the review checklist follow, and [Upgrading](?path=/docs/guidance-upgrading--docs) says what each part's status promises, what each version breaks and deprecates, and what code written against an earlier API is written as now.
- **Tokens** are the sheets: the palette ramps, the semantic colours in both modes, the type ramp, the space scale, shape and the control metrics. Each sheet is read from the generated docs, so it is the build, not a drawing of it.
- **Primitives** are the layout and text elements every screen is made from.
- **Components** are the parts: buttons, badges, controls, tabs, overlays and the rest, each with representative examples and a page with usage guidance.
- **Layout** is the application frame: the Shell and its areas, PageHeader, Section and PageSkeleton, with page examples.
- **Patterns** are the repeated interactions built from components: DataTable and its Toolbar, the pickers, previews, Forms, Editable, Composer and Chart.

Switch the **Mode** toolbar above to see any page in dark, **Contrast** for the increased-contrast values, and **Direction** to lay it out right to left.
