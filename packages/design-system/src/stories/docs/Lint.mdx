# Lint rules

The package exports an ESLint plugin, `@ledger/design-system/eslint`, whose allowlist is generated by the token build, so the rules and the tokens cannot drift. It has two presets: `package`, what this package lints itself with, and `recommended`, for a product. This is the one table of the rules; the repository's component library guide links here. Each rule also has a page, `eslint-plugin/docs/<rule>.md`, which ships with the plugin and which every finding's `meta.docs.url` points at: what the rule reports, why, what to write instead, examples, its fixes, its allowances and its limits. The [Lint rules reference](?path=/docs/guidance-lint-rules-reference--docs) carries every page, and the table's Page column links each rule's section.

1. In the package's stories, `no-arbitrary-value` is off: a story's own frame may take a fixed width. A class has one owner, so no other rule reports an arbitrary value or a variable shorthand there. `no-non-token-class` is an error there as everywhere, so the parts a story demonstrates stay on the tokens. The five usage rules (`no-overlay-autofocus`, `no-disabled-while-loading`, `overlay-width-preset`, `link-button-navigation`, `no-style-design-value`) are off there too, because a Don't story shows the mistake on purpose.
2. Off in `primitives/bleed.tsx`, the one place a negative margin is written. A class has one owner, so no other rule reports a margin there, at any key; a `dark:` margin is `no-dark-variant`'s, which is on there.
3. Opt-in product layout rules, off in both presets: filled tabs and horizontally scrolling comparison tables remain supported by the kit. A product that adopts the contract turns them on for its product files; this repository's application does. Each required prop must follow any spread so the spread cannot override it.
4. Inside the package, a file may keep a counted allowance for a rule in `test/lint-allow.json`: the rule fails when the file has more reports than its allowance, and when it has fewer, until the allowance is lowered. The list may only shrink.
5. On in stories and in `bleed.tsx` too. A configuration comment or a block disable turns a rule off for the rest of the file, so it is reported even with a reason; a line or next-line disable keeps one site out, and says why. A next-line disable that names no rule, bare or with a list of only commas or empty quotes, turns every rule off for its line, so it is reported too. Comments are read as ESLint reads them, so a rule name written with an escape (`"ledger\u002fno-margin"`) is still that rule. In this repository `scripts/check-allow-lists.mjs` counts every inline directive that names a ledger rule, and every disable that names none, per file in the application's and the package's source; the counts may only shrink, and the application keeps none. An entry under a rule is where that rule's count starts only in the change that adds the rule to the plugin and to this page. A disable that silences nothing fails the lint (`reportUnusedDisableDirectives: "error"`), and an `eslint-suppressions.json` may not carry a ledger rule: the application has none, and the package's lists other rules only.

The table's rows are generated from the rules' pages by `npm run build:lint`, and `test/lint-docs.test.mjs` checks them against the plugin: it fails when a rule has no page, a page's sections are not the seven in order, a reported example is not reported by its rule or is reported by another, an allowed example is reported at all or does not compile against the kit, a preset column disagrees with the preset, a rule's `meta.docs.url` is not its page, or this table or the reference has drifted from the pages.

`test/lint-meta.test.mjs` holds every rule to its kind, its description, its page, its words in `meta.messages` and a preset (or the two opt-in rules), and to a case file in `test/lint-cases/` whose invalid cases reach every message id. `test/lint-messages.test.mjs` renders every message into `test/lint-messages.snap.md`, with every value a rule's data gives its words (advice, presets, retired names), and fails when one changes; each is at most 300 characters before its note, ends with a period and pairs its brackets and quotes, and every rule is held to leading with its subject and to giving no configuration advice, as What a finding names describes. In this repository `npm run check:lint-changelog` fails a change to the plugin or its token data that has no entry in the package's CHANGELOG, unless every commit that changed those files ends its message with the line "Lint: no behaviour change"; a change not yet committed always needs the entry.

Inside the package a portability rule also blocks any import from a consumer (`@/…`), from the prototype, or from a router.

## One owner per class

Each class the eight class rules read is reported by one of them, the one whose fix takes the whole class away or rewrites it; a rule whose fix would leave the class broken never owns it. The owner is the first of these the class fails: `no-dark-variant` (any `dark:` class, a margin included), `no-margin` (any other margin, at a token key, a stock key, an arbitrary value or a variable), `no-unknown-variant` (any other class under a variant Tailwind does not generate, such as `hovr:`, `tablet:` or `hover/row:`, which generates no CSS whatever its base, or under an `aria-` variant that names no ARIA attribute or a variant whose value is a CSS variable, `nth-(--n):`), `no-arbitrary-value` (a bracketed value, or Tailwind 4's variable shorthand such as `w-(--rail)`; a Ledger token's variable with a token class that generates the same CSS, `bg-(--ds-elevation-surface)`, is fixed to it), `no-alpha-token` (alpha on a token colour), `no-static-design-value`, `no-deprecated-token`, then `no-non-token-class` for the rest, with a cause in its message: a shadcn theme name (`text-muted-foreground`, `bg-muted/50`), a Tailwind palette colour with alpha (`bg-red-500/50`), a minus on a padding, gap or size, which Tailwind does not negate (`-p-200`, `-w-full`), a class built at runtime, or an unknown class, which it names further when it can: a stock colour or step (`bg-red-500`, `p-4`), a stock width or height (`w-4`), a key off the space scale (`p-210`), a step past a numbered series (`fill-chart-categorical-9`) or a misspelt token class (`bg-surfce`). So `mt-[13px]` is a margin, `dark:bg-white` and `dark:mt-4` dark classes and `bg-red-500/50` a palette colour, each reported by one rule. A rule about a part may quote a class too: `overlay-width-preset` names the width class on a DialogContent, SheetContent or AlertDialogContent (`max-w-[520px]`), which the class's owner also reports. `classify` in `eslint-plugin/classes.js` holds the order, and `test/lint-ownership.test.mjs` shows that no stock class is reported twice and that every rule reports the same alone, with the others or after them.

## What a finding names

Every message keeps one contract, which `eslint-plugin/report.js` states and `test/lint-messages.test.mjs` holds for every rule: the subject first, as written (a quoted class, a `<Tag>`, a `style.x`, a `call()`), then what it is, one clause of why when that is not obvious, and what to write instead, the Ledger token, prop value or part, at most two, computed from what was written. It never offers the configuration as the fix: no allowance, no disable, no "declare a token" or "add a variant", since a missing token is a kit change through `/ledger-add-part`. What it names is chosen by role, never by value alone:

- **A value names the nearest token of its role's family.** A stock step, an arbitrary value, a numeric utility or a literal in a style is named by the token nearest its value, from the family its property's role takes and no other: `space.*` for padding, gap, inset and translate, `border.width.*` for a border or outline width, `radius.*` for a corner, `font.*` for a text size and then a weight, `motion.duration.*` for a duration, the two opacities and the drop shadows. A value one token holds names it (`"p-4" is Tailwind's spacing step 4 (16px), … 16px is p-200 (space.200).`), a value between two steps names both, and one off the scale names the scale's range. A width or a height names no token, whatever its value: a container or breakpoint threshold, a layout region's width and a part's own size (`dimension.part.*`, that part's alone) are never offered, and the message says `A width is a layout part's, a part's preset or computed from its container (w-full, a grid track).`, with an example of the dimension (`h-full` for a height), except that 1px is its own spelling (`h-px`). A viewport length is structure and gets no hint. Zero is `space.0`, a radius from 32px up is a pill's (`rounded-full`), and a text size whose type style also sets a weight names the weight. On an element `use-primitives` reads, in a product, a padding or a gap is named as its primitive's prop (`padding="space.200" on a Box`), since that rule reports the class there; `space-x` and `space-y` name the parent's space.
- **A colour names the roles its hue plays** (decision 8 of the lint hardening plan): at most two, each with its purpose (`Red is bg-danger-bold (a vibrant background for critical information…) or bg-accent-red-bolder (…)`), in the state its variant asks for, a hovered token under `hover:` and a disabled one under `disabled:`. It names one token alone only when one role holds the colour within ΔE 0.02 in both modes, which a palette colour alone never is, since no token keeps one colour in both; when two roles hold it, it names both. Greys differ by elevation, not by value (a white page is the surface, a grey as pale is sunken or raised), so a grey pair gets one token only where the site names its role with a token twin. A pale tint is its hue's, read by its lightness as well as its chroma (`#fef2f2` is red). A `dark:` colour is ranked with its light twin on the same site, in both modes: `no-dark-variant` says when the twin is a token that already changes with the mode, so dropping the `dark:` class is the whole fix, and otherwise which tokens replace both classes.
- **A shadcn theme name names the Ledger class for its job.** `text-muted-foreground`, `bg-background`, `ring-ring` and the rest of shadcn's 39 colour names generate no CSS here, and `no-non-token-class` names each by the class that does its job (`text-subtle`, `bg-surface`, `outline-focused`), from one table, `build/vocabulary-aliases.json`. The token build checks it (each name is no Ledger class and generates no CSS; each class it names is one the allowlist lists, and neither deprecated nor for one purpose only), and `npm run build:lint` writes it onto the [Coming from shadcn](?path=/docs/guidance-coming-from-shadcn--docs) page. `bg-accent` adds that Ledger's `accent-*` colours are hues with no meaning. Under a state variant its entry keys, a name takes that state's class: `bg-selected` for a selected, checked or pressed item, `text-subtlest` for a placeholder.
- **Layout names the part, and a prop its value.** `use-primitives` names the part a plain element's classes make, with its props and their values: a flex row is an Inline, a flex column a Stack, a grid a Grid (`<Inline space="space.100">`). `no-margin` names the parent's `space` at the margin's step, and Bleed for a negative margin, bracketed ones included, up to Bleed's widest step, `space.400`. `no-alpha-token` names the token's own states by the alpha: its tints at `/30` and under, only ones quieter than the token, its hovered and pressed states at `/60` and over (its quieter tints where it has no state), one of each between, and the state its variant asks for first; a band with nothing names nothing. `overlay-width-preset` names the nearest step of the part's own width map (`width="medium"` (520px)), which `npm run build:lint` reads from Dialog, Sheet and AlertDialog into `eslint-plugin/components.json`; the steps are the parts', not tokens.

While the lint data is stale, nothing is taken from `lint-values.json`: a finding keeps its rule's general words and offers nothing.

**Fixes and suggestions.** `--fix` writes only what has one answer: `no-deprecated-token`'s and `no-deprecated-name`'s one-to-one replacements, and `no-arbitrary-value`'s token variable to the token class that generates the same CSS. Where one class stands for the class written, a finding also carries an editor suggestion: a misspelt variant's or token class's respelling (`hovr:`, `bg-surfce`; within the class's own utility, never another emphasis of one token, and never a class Tailwind names by a value keyword such as `min-h-dvw`), a stock or arbitrary value that one token of its role holds exactly (`p-4` becomes `p-200`, `text-[13px]` `font-body`), a colour one role holds within ΔE 0.02 in both modes, and a theme name's Ledger class, one for each where the table names two. A suggestion is the reader's choice, applied in the editor; `eslint --fix` never runs one. It keeps the class's variants and `!`, rewrites that class alone where it is written (a class in a template gets none), and writes only a class no Ledger rule reports, which `test/lint-fix-safety.test.mjs` and `test/lint-nearest.test.mjs` check for every suggestion they reach. A value between two steps, a value two tokens hold (`border-2`, selected or focused), a width, a colour's roles and a padding or a gap that `use-primitives` reports on its element are named and never offered, since which one is right depends on the part.

## What counts as structural

Display, position, alignment, overflow, text flow and interaction utilities are allowed as written, because they carry no design value: `flex`, `grid`, `relative`, `absolute`, `sticky`, `truncate`, `whitespace-nowrap`, `select-none`, `pointer-events-none`, `overflow-auto`, `overscroll-none`, `sr-only`, `cursor-pointer`, `transition-colors`, `animate-spin` and their kin. Alignment takes the values Tailwind generates for each property: `items-center-safe` and `items-baseline-last`, `justify-evenly` and `content-between`, but no `items-between`. Sizes with a token key are allowed on every sizing property: `w-200`, `min-h-800`, `size-150`. A leading minus is allowed where Tailwind negates the utility (`-inset-x-100`, `-translate-y-full`, `-indent-200`), never on padding, gap or a size (`-p-200` generates no CSS), and never before `auto`. A number is written as Tailwind reads it, with no leading zero and at most 15 digits (`order-2`, `line-clamp-3`, not `order-02`). Every spelling the lint admits generates CSS, which `test/lint-tailwind.test.mjs` asks Tailwind, with two kinds of exception that generate none by design: the name markers `group` and `peer` (named or not, `group/row`), which a variant reads, and `recharts-cartesian-axis-tick-value`, the tick class the chart library reads to measure its ticks. A grid template whose tracks carry no length is structure too, since it sizes to content or shares the free space: `grid-cols-[auto_1fr]`, `grid-cols-[minmax(0,1fr)_auto]`, tracks of `auto`, `min-content`, `max-content`, `<n>fr` or `minmax(0,…)` of one of those, or a lone `subgrid`. A template with a length, `repeat()` or `var()` in it is still an arbitrary value. Two classes that read a variable are structure as well: Grid's responsive columns (`grid-cols-(--ds-grid-md)`, one per breakpoint) and a disclosure panel's measured height (`h-(--accordion-panel-height)`, `h-(--collapsible-panel-height)`). The kit's own utilities are allowed as well, by the name each `@utility` in its CSS declares, which the token build reads into `lint.json`: the layout rules in `layout.css` and `shell.css` (`page-header`, `section-header`, `fill-window`, `sticky-rail` and the shell regions), `stat-grid` with `stat-grid-2` to `stat-grid-6` in `stat.css`, the hit areas `touch-target`, `touch-target-block` and `touch-target-block-after` in `touch.css`, and the motion, drawer and toast utilities. A utility the CSS gains passes with no edit to the lint, and one it loses fails.

## What the lint cannot see

The rules read one file at a time, as it is written. Each rule's page lists its own limits; across the rules they do not see:

- **A value from another file.** A class, a style object or a handler imported from another module is not read where it is used. A module-level class string, or a module-level map or list of them, is checked where it is declared instead, when it reads as classes: at least half of a string's words are classes the lint knows, and most of a map's strings are, a bare word left out (`"flex"` is also a CSS value, `"hidden"` an attribute, so a style object or a list of attributes or views is no class map). What the map holds is read through an `Object.freeze`, a same-file spread, each branch of a condition, a template's own text and the values of `Object.fromEntries` or `new Map`. The token build's output under `src/generated` is not read there. A string of stock classes exported for another file passes, and so does a map's data: a bare word no rule knows (`"danger"`, `"none"`), or a key whose values across its records are mostly not classes. A map a call builds (`(() => ({ … }))()`, a function that returns one) is read only where a class site in the file reads it.
- **What only runtime knows.** A prop, a spread of props, a variable changed other than by assigning it (`k++`, `k.a = …`, `list.push(…)`) and a function from another module are not read; `readable-classes` reports such a variable on a kit part as written again. What the file writes itself is: a `const`, a `let` or `var` with each value assigned to it, a destructured slot, an entry of a map, a list, an enum or an `Object.freeze` (every entry, a computed key's too, for a key such as `tones[tone]` known only at runtime), a key a helper's object computes from a same-file value (`cn({ [active]: on })`), each entry of a same-file list a `.map` callback walks, a same-file function's, a `useMemo`'s or a `useCallback`'s result, with each parameter read as the call gives it (`note("text-danger")`), `useState`'s first value, a spread of a same-file object, and a DOM element's classes written to `className` or given to `classList.add` and `classList.toggle`. A `Map` read with `.get`, and a pair destructured from `Object.entries(…)`, are not followed to their values. A class built in a template or a concatenation (`` `bg-${tone}` ``, `"bg-" + tone`) is never read as its fragments: `no-non-token-class` reports it once as a class built at runtime. A class glued together by a list's `.join("")` or a string's `.concat(…)` is the same. A hole whose values bring their own space (`` `flex${on ? " gap-100" : ""}` ``) builds nothing, and is read. On a kit part's `className`, in an object spread onto the part or in a slot map it is given, what the rules cannot read is not passed in silence: `readable-classes` reports it where it enters, whether a prop, an import from the product's own modules (held in a `const` too), another package's function the file hands values to, or a call, and offers the part's own props.
- **A restyle from outside the part.** A variant on a parent that reaches into its children (`*:`, `[&_button]:`) is judged by its utility, not by what it reaches.
- **A part behind a local component.** A rule that judges a kit part knows it by its import from `@ledger/design-system`, by name, alias or namespace (inside the kit, by a relative import), and a type of the same name hides nothing; `cell-plain`, `id-not-blue`, `use-primitives` and `button-icon-slot` also follow a `render` that puts the part in an element's place. A local component that renders the part is not the part: a class passed to `<NameCell className="font-semibold">`, which `NameCell` forwards to a `Table.Cell`, is checked as a class where it is written, not as the cell's.
- **A style written elsewhere, and what a style may hold.** `no-style-design-value` and `overlay-width-preset` follow a style to where the file writes it: either branch, a `const` or a map's entry, an object spread in or merged by `Object.assign`, a Base UI style callback (memoised by `useCallback` too), and what a same-file function returns, with each parameter read as the call gives it, or `useMemo` memoises. In a style's values `no-style-design-value` also follows a prop's default, a string in a template's hole or a concatenation, a number written before a length unit (`` `${W}px` ``), a named number in a sum and a product whose every factor the file writes, and a `var()`'s fallback; `no-raw-colour` follows a colour attribute's value, and the records a chart's data holds, the same way. A finding on a literal written elsewhere says where. A received `style`, the value a caller passes, a call the file cannot follow, a factor the page computes (`depth * INDENT`), `token()` and `var()` without a fallback are what only the running page knows, and pass. A viewport length (`100dvh`, `90vw`, `10dvh` inside `min()`) is the window's own size, structure as `100%` is, and in the kit's own source the widths and heights of the Dialog and Sheet preset maps (`dialogWidths`, `sheetWidths`) are the one place for their steps, so neither is read as a design value. A part's own size (`dimension.part.*`) is read by that part alone.
- **What a value is for.** A finding's advice reads the class or the style property, its variants and the other classes on the same site, never what the element is for: it names a value from its property's family, a width by no token and a colour by the roles its hue plays, and which role is right is the reader's call (`bg-white dark:bg-gray-800` names `bg-surface-overlay` and `bg-neutral`, the nearest in both modes, whatever the element is). A `dark:` colour's light twin is found only on the same site, one class of its utility on each side, and a palette colour on a utility where its hue plays no role (`ring-*`, `outline-*`, `divide-*`, `border-teal-500`) is reported with no name.
- **Plain CSS.** A stylesheet is outside the rules, so a product's CSS is not read: a utility or a variant it declares (`@utility`, `@custom-variant`) is not in `lint.json`, which the token build reads from the kit's CSS alone, and a class that uses one is reported, unless `settings.ledger.customVariants` names the variant. The kit's own, `src/styles/*.css`, is held to the tokens by `test/css-tokens.test.mjs` instead: no literal colour outside a `var()` reference and `theme()`, a length only as 0, 1px (the hairline, which a style reports as any other length), a percentage, a viewport or container length or a token (a `var()`'s fallback read as a value of its own, and a number times a length read as that length), `@media` and `@container` conditions from the theme, and no `@apply`. A literal that no token of its value and role holds yet is counted, with its reason, in `test/css-token-allow.json`, which may only shrink. In a component file, a `<style>` element is `no-style-design-value`'s, and a colour attribute on an SVG element or a recharts part is `no-raw-colour`'s.
- **The files where a rule is off, and the sites that waive one.** In the package's stories `no-arbitrary-value` and the five usage rules are off, and in `primitives/bleed.tsx` `no-margin` is. A class has one owner, so where its owner is off no other rule reports it: an arbitrary value or a variable shorthand in a story (`w-[240px]`, `w-(--rail)`, `bg-brand-bold/[0.5]`), and a margin at any key in `bleed.tsx` (`mt-4`, `mt-[13px]`); a `dark:` class is `no-dark-variant`'s in both. The same holds at one site: a line disable, an allowance or a bulk suppression of a class's owner waives the whole class, so a margin that is also a stock key or an arbitrary value (`my-2`, `-mx-[13px]`) under a disable of `no-margin`, or a variable shorthand under an allowance of `no-arbitrary-value`, is reported by no other rule. `test/lint-ownership.test.mjs` pins all three.
- **The plugin under another name.** `no-inline-config` and this repository's directive count know the rules as `ledger/…`. Registered under another name (`plugins: { ds: ledger }`), a comment that turns `ds/no-margin` off is not reported or counted. The presets register it as `ledger`; keep that name.

What crosses files, such as where focus returns or whether a custom link renders an anchor, is checked by the browser suites.

## What the lint knows of Tailwind

The rules never load Tailwind. The token build asks it once, in `build/lint-data.mjs`, which `npm run build:tokens` runs after the tokens, and writes the answers beside the allowlist. `src/generated/lint.json` holds what a file may need: the name of every `@utility` the kit's CSS declares; the utilities a leading minus negates; the variant grammar, with the breakpoints and container sizes and their values, the static variants that are a media query around a selector (`hover`), which a negation splits in two, and the roots that take a CSS variable as their value (`nth-(--n)`), which no selector reads; the ARIA attribute names, aria-query's and the three ARIA 1.3 adds that it lacks; shadcn's theme names, so a class is known as one without the values; and the hash of each file the data was built from. `no-unknown-variant` checks every variant of every class against that grammar, compounds through to the variant they wrap. `src/generated/lint-values.json` holds what only a finding's advice needs: each `@utility`'s file, line and the properties it sets; each token's value (a length in px, a duration in ms, a colour in OKLab as the reader sees it in each mode); the token behind each token class; which token class generates the same CSS as a token's variable written in a class (`bg-(--ds-elevation-surface)` is `bg-surface`, `p-[var(--ds-space-200)]` is `p-200`), each pair checked against Tailwind, which `no-arbitrary-value` fixes to; the properties of each utility that takes a space but no minus, which `no-non-token-class` names; the Ledger classes for each of shadcn's theme names, from `build/vocabulary-aliases.json` as the build checked it; and Tailwind's stock scales and palette, which a finding's nearest token is ranked against. A rule reads `lint.json` on the first file that needs it and `lint-values.json` only when a finding needs a value. Both ship with the package, in `src/generated` and `dist/generated`, and are read from the same one; `ledger.css` keeps them out of Tailwind's scan, since they spell classes no element renders.

The data reflects Tailwind 4.3.3, the release the kit is built and tested with, and `lint.json` records it; on another Tailwind 4 release a variant or a utility may generate CSS the data does not describe. The breakpoints are the kit's seven (`sm`, `md`, `lg`, `aside`, `panel`, `wide`, and `xl`, the alias of `panel` behind Grid's `xl` column count): the reset clears Tailwind's, so `2xl:` generates nothing. The data is stale when, in the kit's checkout, a file it was built from (the allowlist, the token docs, a stylesheet or the theme-name table) has changed since the build, or when `lint-values.json` comes from another build than `lint.json`. Whichever of `no-arbitrary-value`, `no-unknown-variant` and `no-non-token-class` runs first on a file says so once, at line 1, naming the file that changed; `no-arbitrary-value` writes no token class until the data is fresh; no allowance counts the finding; and `npm run build:tokens` fixes it. A product's installed package ships without the token docs, so its lint compares no file and pays nothing for the check. A missing or unreadable file stops the lint with an error that names it.

## When a finding looks wrong

- **Read the rule's page first.** Its examples show what it reports and what it allows, and its Limits say what it cannot see.
- **The tokens or the exports changed.** The allowlist and the theme-name table come from the token build, and the part names, each part's styling props and the overlays' width steps from the source: run `npm run build:tokens` after a change to the tokens or to `build/vocabulary-aliases.json`, and `npm run build:lint` after a change to the exports, a part's props or an overlay's width steps, then lint again.
- **A cached run.** The plugin reads its data once per process, the first time a rule needs it, so `eslint --cache` or an editor's ESLint server can keep a result across a token rebuild. Run without `--cache`, delete `.eslintcache`, or restart the server.
- **The kit is linted on its own.** The repository's root `npm run lint` ignores `packages/`; the kit lints itself with `npm run lint -w packages/design-system`, under `configs.package`.
- **Tailwind generates a class the lint rejects.** The lint admits the tokens and the documented structural utilities only. A missing token or part is a kit change through `/ledger-add-part`, never an allowance or a disable.

## Corpus ratchets

In this repository `npm run lint:corpus` lints two corpora, and `npm run lint:corpus -- --check`, a step of CI, holds them to `scripts/lint-corpus-baseline.json` as committed at the base ref.

- **The clean corpus** is the application's product files and this package's source, stories included, each under its own config, with every allowance and inline disable taken off. Its count per rule may only fall: a rise means a rule now reports code it passed before, so the code or the rule changes, never the count. A rule new to the plugin starts its count. A rule the base counts and the plugin no longer has fails until the baseline says what became of it: `"renamed": {"ledger/old": "ledger/new"}` holds the new name to the old count, and `"removed": ["ledger/old"]` lets the count go.
- **Where each rule runs** is recorded beside the counts: the configs' global ignores, and every block that sets a ledger rule, with its files and ignores. A block that turns a rule off for a file, an ignore or a narrower glob hides reports the way an allowance does, with no count, so every file the base had keeps each rule the base's config ran on it. A new file takes the reach its config gives it.
- **The stock corpus** is `test/fixtures/stock-classes.json`: the class strings of shadcn's registry, from `@shadcn/lint` under its MIT notice and pinned to that file's hash by the script's tests, and a hand list of Tailwind's palette and scales. Each class is linted on its own element in a product file, and the baseline names the classes no rule reports on. The corpus may only grow, so a class cannot leave with its verdict. A class the base reported that starts to pass is named in the baseline's `stock.admitted` in the same change, with a pointer to the page that makes it structural, `docs/guides/component-library.md` or this page's What counts as structural (`packages/design-system/src/stories/docs/Lint.mdx#what-counts-as-structural`); that page names it in backticks, as written, as its utility without variants, or as its utility's prefix followed by an asterisk. The number of the base's classes that two or more rules report may only fall.

After a change that moves a count, the reach or the corpus, `npm run lint:corpus -- --update` rewrites the baseline and lists what moved, each rule that gained or lost a file and each stock class that changed verdict included; commit it with the change, since `--check` also fails when the baseline is not the tree's own measurement. `--update` keeps `renamed`, `removed` and `stock.admitted` and never writes them. `-- --rule <rule>` prints every finding of one rule in both corpora. `-- --digest` prints a hash of every finding (file, line, column, rule and message), the same on every run over the same tree, which shows that a refactor of the lint changes no finding. In CI a push's all-zero base stands for the commit before HEAD, and a shallow clone without it fails rather than compare with nothing.

## Running it

```js
// eslint.config.js in a product
import ledger from "@ledger/design-system/eslint";

export default [
  ...ledger.configs.recommended,
  // The two opt-in layout rules, for the files that follow the product contract.
  {
    files: ["src/routes/**/*.tsx"],
    rules: {
      "ledger/product-responsive-table": "error",
      "ledger/product-line-tabs": "error",
      // A rule's findings end with its note: where this product's own part stands in for the kit's.
      "ledger/no-native-confirm": ["error", { note: "In this app: useConfirmation." }],
    },
  },
];
```

Every rule takes a `note` option, a sentence of at most 200 characters that each of its findings ends with, for what the kit cannot know: the product's own binding of the advice. `settings.ledger.note` gives every rule one, before the rule's own. A note that is not a string, or is too long, is named once on stderr and ignored.

The class rules read the helpers `cn`, `clsx`, `twMerge` and `classes`, and `cx`, `twJoin` and `classNames` where the file imports them (a chart's own `cx` is not one), clsx-style (an object's keys are classes); and `cva`, and `tv` where the file imports it, by their configs (`base`, `slots`, `variants` and a `class` or `className` are classes; `defaultVariants`, `responsiveVariants`, `extend` and compound selectors are names; tv's first argument is always a config, and cva's is its base unless it has a config's key). An import of `cn` from the kit, or of clsx, classnames, tailwind-merge, class-variance-authority or tailwind-variants, counts under another name (`import { cn as merge }`) and through a namespace (`u.cn`), and so does a const that holds a helper (`const merge = cn`). `settings.ledger.classFunctions` names a product's own helpers read as `cn` is, and `settings.ledger.variantFunctions` those read as `tv` is; each takes a name, or a list of names, as the helper is called. `settings.ledger.customVariants` names the variants a product declares in its own CSS with `@custom-variant`, as a class writes them before the colon, which `no-unknown-variant` then knows, alone and inside a compound, in every file of the run. A value the lint cannot use is named once on stderr and ignored.

`configs.package` sets `settings.ledger.kit` to `"self"`. In the kit's own source a part imported by a relative path (`./button`, `../components/table`, a barrel) is then the part, as an import from `@ledger/design-system` is in a product, and so is a part's own top-level declaration; an import from `src/stories` or `src/lib`, and a story's or a helper's own component of a part's name, is no part. A product leaves it unset, and any other value is named once on stderr and ignored.

```sh
# inside the package
npm run lint

# in a product, after adopting the preset
npx eslint src
```
