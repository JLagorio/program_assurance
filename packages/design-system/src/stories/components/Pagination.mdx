# Pagination

Navigation between pages using [shadcn’s flat Pagination parts](https://ui.shadcn.com/docs/components/base/pagination). The caller owns page state, URLs and result counts.

## Anatomy

```tsx
<Pagination aria-label="Control pages">
  <PaginationContent>
    <PaginationItem>
      <PaginationPrevious href="?page=1" />
    </PaginationItem>
    <PaginationItem>
      <PaginationLink href="?page=2" isActive>
        2
      </PaginationLink>
    </PaginationItem>
    <PaginationItem>
      <PaginationEllipsis />
    </PaginationItem>
    <PaginationItem>
      <PaginationNext href="?page=3" />
    </PaginationItem>
  </PaginationContent>
</Pagination>
```

Root is a nav, Content a list and Item a list item. Link uses a real anchor with the shared Button recipe. Base UI 1.7 Button adds button semantics even when rendered as an anchor, so Ledger preserves native link semantics here. Previous and Next are links with localized names, optional `text` and direction-aware icons.

## Variants and states

`isActive` sets `aria-current="page"` and the selected appearance. All links accept native anchor attributes, events and refs, including href, target and rel. Ellipsis is decorative.

Previous and Next carry their words where the pagination has 384px of its own width and are arrows below it, named for a screen reader either way. The region measures itself, not the window, so the same pagination has words on a page and arrows in a 320px panel on the same screen. A pagination holding Previous or Next is a size container, so its width comes from where it sits, not from its links. It spans its container by default. At the end of a row, give it the rest of the row with `min-w-0 flex-1 justify-end`: its words show where that leaves 384px, and a narrower row shrinks it to arrows. Sized to its content instead (`w-auto`, an `auto` grid column), a pagination with words is 384px whatever its links need, so a longer list wraps inside it. Previous and Next read that width from their `Pagination` root; outside one they show arrows only. The list wraps rather than running past a narrow frame, and every link is at least 28px.

## Accessibility

Name each navigation region distinctly. Use links for URLs and buttons for local state changes. An unavailable link needs caller-owned semantics and activation handling; anchors have no native disabled attribute. Prefer omitting unavailable navigation links or rendering a disabled Button for an in-memory pager. RTL arrows follow the enclosing direction.

## Props

The configured `page`, `pageCount`, `onPageChange`, `total`, `pageSize` and `label` API is removed. Use native `aria-label` and explicit children. DataTable retains its page-size and table-state API; its internal composition preserves result counts and page controls.
