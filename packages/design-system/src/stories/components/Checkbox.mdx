# Checkbox

An independent boolean choice, using the shadcn Base UI root and indicator. The 16px control supplies the check or mixed-state dash; labels and descriptions are composed outside it.

```tsx
<label className="inline-flex items-center gap-100">
  <Checkbox name="pii" value="yes" defaultChecked />
  Handles PII
</label>
```

Use [RadioGroup](?path=/docs/components-radiogroup--docs) for one selected answer from visible choices, or [Switch](?path=/docs/components-switch--docs) for an on/off setting. The caller decides when to save a change.

## Selection and mixed state

Use boolean `checked` with `onCheckedChange(checked, details)`, or `defaultChecked` for local state. `details.cancel()` rejects a change. `disabled` prevents interaction and removes the control from the tab order; `readOnly` keeps it focusable without allowing changes.

Mixed state uses a separate boolean `indeterminate` prop. A select-all control can derive `checked={allSelected}` and `indeterminate={someSelected && !allSelected}`, then update every child in `onCheckedChange`. [Table.Selection](?path=/docs/components-table--docs) uses the same two booleans.

The existing Base UI `CheckboxGroup` can also own the selected values and derive a `parent` checkbox's mixed state. Import that grouping primitive from `@base-ui/react/checkbox-group` when using this composition:

## Labels, Field and forms

A wrapping label names the checkbox and toggles it when clicked. A sibling label uses `htmlFor` with the checkbox's `id`. Use `aria-label` for a control with no visible label. Put supporting text in an element referenced by `aria-describedby`.

Compose [Field](?path=/docs/components-field--docs) with FieldLabel and FieldDescription/FieldError. Associate the checkbox through `htmlFor`/`id` and `aria-describedby`; pass `aria-invalid` and `aria-required` explicitly. For several checkboxes, use FieldSet/FieldLegend and give each choice its own label. Requiring the group does not require every checkbox. Native `required` enables browser validation.

`name`, `value` and `form` control native submission. A checked checkbox submits its value (or `on` when omitted); an unchecked checkbox is omitted unless `uncheckedValue` is supplied. Native form reset is caller-owned in Base UI 1.7: restore controlled `checked` state in `onReset`.

## Native props and keyboard

The default root is a span with `role="checkbox"`, plus a hidden input. `ref` targets the visible control; `inputRef` and `id` target the input. For a native button root, use `nativeButton` with `render={<button />}`; `id` then belongs to that button. The render element's props, classes, styles, handlers and refs are merged. `className` and `style` accept Base UI state callbacks.

Each enabled checkbox is a Tab stop. Space toggles it. Enter does not toggle it; inside a form it activates the default submitter. Mixed state is announced as `aria-checked="mixed"` and drawn with a dash.

## Migration

Move label children into an external label and replace `description` with supporting content linked by `aria-describedby` or FieldDescription. Replace `checked="indeterminate"` with `checked={false} indeterminate`; callbacks now receive a boolean and cancellable event details. Use `render` for composition. The root follows Base UI's default span and input structure.
