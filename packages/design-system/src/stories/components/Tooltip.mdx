# Tooltip

A supplementary visual label on hover or keyboard focus, using shadcn's Base UI composition. IconButton already draws one from its `label`; only compose a separate tooltip when its content differs, such as a keyboard shortcut.

```tsx
<TooltipProvider delay={300} timeout={300}>
  <Tooltip>
    <TooltipTrigger render={<IconButton label="Search" icon={<Search />} isTooltipDisabled />} />
    <TooltipContent>Search <Kbd>K</Kbd></TooltipContent>
  </Tooltip>
</TooltipProvider>
```

## Composition

Root owns open state. Trigger renders a button by default; `render` composes an existing button, link or span with its native props, handlers and ref. It does not give a rendered link or span button semantics, and has no `nativeButton` prop. A custom trigger must accept merged props and its ref.

Content includes the portal, positioner and decorative arrow. Native props, `ref`, `render`, and state callbacks for `className` and `style` target the popup. Placement defaults to top/center with `sideOffset={4}` and `alignOffset={0}`; those four positioning props belong on Content. Logical sides follow the Ledger locale or Content's explicit `dir`.

The surface retains Ledger's bold neutral fill, inverse text, small body text and spacing tokens. Its maximum width is 320px, constrained by available space; use native `style` to override it. The arrow uses Ledger's 8px size and small radius. Content stays inside an enclosing dialog's portal boundary so it remains visible and hoverable there.

## Timing and interaction

TooltipProvider shares hover timing across a group. Its shadcn default is `delay={0}`; Base UI's `timeout` defaults to 400ms. Shell and Storybook explicitly use `delay={300}` and `timeout={300}` to preserve the product's timing. Without a provider, Base UI uses a 600ms trigger delay and no shared group; no local fallback provider is created.

Trigger accepts `delay`, `closeDelay` and `closeOnClick`. An adjacent tooltip opens immediately during the provider's timeout. Keyboard focus opens without the hover delay. Pointer passage into the popup keeps it open; leaving both, moving focus away, clicking the trigger or pressing Escape dismisses it. Trigger clicks close by default; `closeOnClick={false}` changes that behavior. Touch retains the trigger's action without opening a hover tooltip.

Use Root's `defaultOpen`, or controlled `open` with `onOpenChange(open, details)`. `details.cancel()` rejects a state change. Generic payloads let several triggers share one Root and provide content through its children function.

## Accessibility and disabled actions

Give the trigger its own accessible name and keep essential instructions visible. Base UI 1.7 does not automatically add `role="tooltip"` or `aria-describedby`; the popup is a visual supplement, not the control's accessible name or description. Keep controls and links out of the popup; use Popover for content the reader needs to interact with.

Trigger's `disabled` disables tooltip interaction; it does not disable the rendered button. Put the native `disabled` prop on the rendered Button. To explain an unavailable action on hover and keyboard focus, render a focusable span around its disabled button, and expose the reason independently in text or the wrapper's accessible name. The application uses this composition in UnavailableAction.

Inside a Dialog, Escape dismisses an open tooltip first while keeping focus on its trigger. A subsequent Escape can dismiss the dialog.

## Migration and API

Move `content` into TooltipContent, the old child trigger into `TooltipTrigger render`, timing onto Trigger or Provider, and placement/styles onto Content. The old 260px maximum and 6px offset become 320px and 4px, with an arrow. Remove redundant outer tooltips around IconButton; use `isTooltipDisabled` when composing custom content.

Props follow Base UI's [Provider](https://base-ui.com/react/components/tooltip#provider), [Root](https://base-ui.com/react/components/tooltip#root), [Trigger](https://base-ui.com/react/components/tooltip#trigger) and [Popup](https://base-ui.com/react/components/tooltip#popup), with the four positioning props added to Content. See [shadcn Tooltip](https://ui.shadcn.com/docs/components/base/tooltip) for its source composition.
