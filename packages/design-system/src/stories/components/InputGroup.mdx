# InputGroup

**Status: Stable.**

Compose an input or textarea with icons, units and actions using shadcn's InputGroup parts. The group supplies the shared border and focus/invalid appearance.

## When to use it

- **A field with something joined to it**: a unit ("days"), a prefix ("$"), an icon, a keyboard hint, or a button that acts on the value (clear, copy).

Not for a field with nothing beside it: that is an [Input](?path=/docs/components-input--docs) or a [Textarea](?path=/docs/components-textarea--docs). Not for buttons joined with no field: that is a [ButtonGroup](?path=/docs/components-buttongroup--docs). Not for searching a collection: that is a [SearchField](?path=/docs/components-searchfield--docs).

## Content

- A unit or a prefix is the shortest form the reader knows ("days", "$") and never repeats the label.
- An icon-only button's `label` names its action and its object: "Clear link", "Clear search".
- The label is the Field's; an addon never stands in for it.

## Anatomy

```tsx
<Field>
  <FieldLabel>Retention</FieldLabel>
  <InputGroup>
    <InputGroupInput type="number" defaultValue="90" />
    <InputGroupAddon align="inline-end">
      <InputGroupText>days</InputGroupText>
    </InputGroupAddon>
  </InputGroup>
</Field>
```

InputGroupInput inside a [Field](?path=/docs/components-field--docs) takes the label, hint and error with no ids, and the whole group draws the Field's invalid border.

<Canvas of={Stories.BoundInField} />

Addons are InputGroupAddon children, and the control is InputGroupInput or InputGroupTextarea, never a plain Input inside the frame (that draws a second border). Set the width through native style or the surrounding layout.

## Variants and states

Addon alignment is `inline-start` (default), `inline-end`, `block-start` or `block-end`. Inline positions follow text direction. Block addons create a header or footer around the control.

InputGroupButton takes Ledger Button variants (`subtle` by default) and Button's `xsmall` (24px, the default) or `small` (28px). With `icon` and `label` it is an icon-only square that `label` names: a clear, a copy or a calendar button. It shows no tooltip, since the field beside it says what it acts on; a control that needs one outside a field is an [IconButton](?path=/docs/components-iconbutton--docs). `xs` and `sm` are the deprecated spellings of `xsmall` and `small`, and `icon-xs` and `icon-sm` the deprecated square forms that `icon` and `label` replace, each kept for one version. The group takes its height from the control in it: a `size="small"` Input or SelectTrigger makes it 28px, and a small button in an addon leaves it as it is.

<Canvas of={Stories.Buttons} />

`align` places an addon; the DOM places it in the focus order. Write the control first and the addons after it: an addon takes its position from `align`, so an interactive addon aligned `inline-start` still follows the input in the Tab order, the order a screen reader meets them in.

The input or textarea supplies the group's focus, invalid, read-only and disabled looks: focus is one continuous 2px edge around the whole group, in the error colour when the field is invalid, as on Input and Textarea; read-only is the sunken surface with a dashed edge. Disabling an addon button does not disable or dim the editable field.

## Narrow

A keyboard hint, an InputGroupText holding a [Kbd](?path=/docs/components-kbd--docs), shows while the group is 256px or wider and steps aside below that, so the input keeps the room; units, prefixes and buttons stay at every width. A group with a hint measures itself as a size container, so give it a definite width (the layout's, `w-full` or a style width), not a shrink-to-fit parent. Squeezed narrower than its addons, the group clips them at its own edge and never paints over its neighbours, but the field is unusable at that width: a row that crowded takes the search as an icon button instead, as the [Shell's top nav](?path=/docs/layout-shell--docs) does below `md` (see Don't).

## Accessibility

Label the control with Field or an explicit accessible name. The group and its addons are not groups of their own to assistive technology: InputGroup takes `role="group"` only when it is given a name (`aria-label` or `aria-labelledby`), for a frame that holds several controls, and drops an unnamed `group` role a composing part hands it, as Combobox's input does. Decorative icons use `aria-hidden`; explanatory text and actions remain available to assistive technology. Give icon buttons accessible names. Addon buttons are real keyboard stops and default to `type="button"`. Clicking non-interactive addon space focuses the input or textarea; custom click handlers can cancel this.

## Props

Group and Addon accept native div props and refs; Text accepts span props. Input and Textarea parts preserve their control contracts and refs. Button preserves Ledger Button's native Base UI composition, loading and disabled behavior. There are no configured content slots.

## Don't

In a row too crowded for a field, the search is an icon button that opens it in a dialog, never a field squeezed beside the row's actions until it is too narrow to type in.
