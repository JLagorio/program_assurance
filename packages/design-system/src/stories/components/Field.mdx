# Field

Compose labels, controls and validation messages with shadcn's Base UI Field parts and Ledger tokens. Field owns layout; the form owns values, validation and native associations.

## Anatomy

```tsx
const id = useId();
<Field data-invalid={invalid}>
  <FieldLabel htmlFor={id}>Owner</FieldLabel>
  <Input id={id} aria-invalid={invalid} aria-describedby={`${id}-message`} />
  {invalid ? (
    <FieldError id={`${id}-message`} errors={errors} />
  ) : (
    <FieldDescription id={`${id}-message`}>Use the full name.</FieldDescription>
  )}
</Field>;
```

`FieldSet` and `FieldLegend` group related controls. `FieldGroup` spaces fields; `FieldContent` groups text beside a control; `FieldTitle` supplies visual text when a wrapping label already provides the association. `FieldSeparator` divides sections, with optional text.

## Variants and states

Field supports `vertical` (default), `horizontal` and `responsive` orientations. Responsive fields change direction inside a FieldGroup container. Mark the wrapper with `data-invalid` or `data-disabled` and pass the actual state to the control. An asterisk belongs in label content; `aria-required` describes the requirement, while native `required` enables browser validation.

Invalid labels and messages use the same error color; a focused invalid input retains its error border and a separate focus outline. Disabled labels use the disabled text token. A FieldLabel wrapping a Field becomes a choice card with hover, checked and keyboard-focus feedback; disabled choices keep a quiet surface. These styles do not disable a control or validate a value.

Labeled FieldSeparator rules stop on either side of the text instead of painting over the parent surface, so they work inside a page, Card or dialog without a background override.

FieldError accepts children or an `errors` array of message objects. It deduplicates messages and renders nothing for an empty result. Children take precedence.

## Accessibility

Use `htmlFor` and a matching control `id` for individual fields. Reference hint/error IDs with `aria-describedby`, and pass `aria-invalid` to the control. Use FieldSet/FieldLegend for checkbox groups and explicitly name a RadioGroup with `aria-labelledby`. Choice controls keep their individual labels. A group requirement does not make every checkbox required.

Native associations work through wrappers and custom components that forward their props. Generate IDs with `useId` when a form can appear more than once. TanStack Form continues to own touched state, validation and submission; focus the first invalid control on failed submission.

Every part forwards the native attributes and ref of its element: Field/Group/Content/Title/Error/Separator use divs, FieldLabel a label, FieldDescription a paragraph, FieldSet a fieldset, and FieldLegend a legend.

### Migration

Replace `label`, `hint`, `error`, `isRequired`, `isGroup` and `controlId` with composed parts and native attributes. `useFieldControl` and automatic child binding are removed. Move group content to FieldSet/FieldLegend; preserve the control's accessible name, description, invalid state and required announcement. Shadcn's Base UI Field uses semantic HTML; it is separate from the optional Base UI Field primitive.
