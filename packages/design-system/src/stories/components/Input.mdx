# Input

**Status: Stable.**

One line of free text, using shadcn's Base UI Input implementation with Ledger control styling. Labels and validation messages belong to Field.

## When to use it

- **One line the reader types**: a name, a title, a reference number, an email address, a web address.
- **Digits that name something**, such as an identifier, a build number or a postcode, with `inputMode="numeric"`: they are text, not a quantity.

Not for several lines, a description or a statement: that is a [Textarea](?path=/docs/components-textarea--docs). Not for a quantity the reader steps or that has a range: that is a [NumberField](?path=/docs/components-numberfield--docs). Not for one value from a known list: that is a [Select](?path=/docs/components-select--docs), or a [Combobox](?path=/docs/components-combobox--docs) when the list is long enough to search. Not for a day, a time or a moment: that is a [DatePicker](?path=/docs/components-datepicker--docs), a [TimeField](?path=/docs/components-timefield--docs) or a [DateTimeField](?path=/docs/components-datetimefield--docs). Not for searching a collection: that is a [SearchField](?path=/docs/components-searchfield--docs). Not for a value that is read where it is shown and never edited there: that is a [KeyValue](?path=/docs/components-keyvalue--docs).

## Content

- The label, the hint and the error are the Field's, in its words ([Field](?path=/docs/components-field--docs), Content).
- A placeholder is an example of the value ("CTRL-0412", "name@example.org"), never the label, an instruction or "Optional": it is gone as soon as the reader types.
- The width says how long the answer is: a year or a code is narrow, a title is wide. The layout sets it, not the Input.

## Anatomy

```tsx
<Field invalid={invalid} required>
  <FieldLabel>Program name</FieldLabel>
  <Input name="program" value={name} onValueChange={setName} />
  <FieldDescription>As it appears on the authorization package.</FieldDescription>
  <FieldError errors={errors} />
</Field>
```

Inside a [Field](?path=/docs/components-field--docs) the Input takes the label, the hint and the error with no ids, and the Field's `invalid`, `required` and `disabled`.

## Variants and states

`medium` is 32px; `small` is 28px beside toolbar actions. Native `type`, `inputMode`, `readOnly`, `disabled`, `maxLength` and form attributes retain their meanings. The layout sets width. Disabled controls leave the tab order; read-only values remain focusable and copyable. Read-only is the sunken surface with a dashed edge and no hover, so a value that cannot change never looks like a field under the pointer; a value never edited where it is shown is a [KeyValue](?path=/docs/components-keyvalue--docs), not a read-only Input. Prefer a soft limit to `maxLength` for anything pasted: `maxLength` cuts the paste off without a word, where a schema check on submit says what fixes it.

Focus draws one continuous 2px edge over the field border, without a gap or a second ring. Invalid fields keep that edge in the error color. The field and its text stay in place when focus changes; InputGroup owns the edge when the input has addons.

## Accessibility

In a Field the label, hint, error, invalid state and requirement reach the input without ids. Outside one, use a label with `htmlFor` and the input’s `id`, `aria-describedby` for hints, and `aria-invalid` and `aria-required` on the input. The Field's `required` only announces; native `required` on the Input is a browser and Base UI constraint. A placeholder gives an example and never replaces the label.

Native `onChange` remains supported. Search clearing and application shortcuts are caller-owned; Input does not install an Escape handler. Use an accessible InputGroupButton when a clear action is needed.

## Props

`InputProps` extends Base UI Input with Ledger's `size`. Refs and events target the native input; `render`, state callbacks for `className`/`style`, and `onValueChange(value, details)` are forwarded. A value change may be cancelled with `details.cancel()`.
