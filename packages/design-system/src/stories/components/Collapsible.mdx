# Collapsible

**Status: Stable.**

One independent disclosure: content the reader opens when they need it. Based on [shadcn’s Base UI source](https://ui.shadcn.com/docs/components/base/collapsible) and [Base UI](https://base-ui.com/react/components/collapsible). Ledger retains its tokens and application layouts.

## Anatomy

`Collapsible` holds the state, `CollapsibleContent` the content that folds, and one of two triggers opens it:

- **`CollapsibleHeader`**, the disclosure header: the trigger inside a heading, the title at the start and a chevron at the end that turns while the content is open, the row tint under the pointer and the focus ring on the keyboard. The tint reaches `space.100` before a title that sits flush with the content under it, so the title lines up with the rows and the tint still reads as a row; the chevron sits `space.100` inside the end. Use it whenever the disclosure has a title: a rail's group, a block of details, a folded list.
- **`CollapsibleTrigger`**, the bare trigger with no heading and no chevron, for a trigger that is something else already (a Button through `render`, a row's own control).

```tsx
<Collapsible>
  <CollapsibleHeader>Provenance</CollapsibleHeader>
  <CollapsibleContent>…</CollapsibleContent>
</Collapsible>
```

<Canvas of={Stories.Header} />

Counts and marks are ordinary children of the header: `<CollapsibleHeader>Derivation <Count value={3} /></CollapsibleHeader>`; they are part of the button's name. An action for the block goes after the header in a flex row, where the header grows; never inside it, because a button cannot hold another.

## Heading level

The header's heading takes the contextual level from the nearest [HeadingLevelProvider](?path=/docs/primitives-heading--docs), a titled Section or a panel's body, and is an h3 when nothing sets one, as Accordion's is. Wrap it in a HeadingLevelProvider for another level: `level={2}` for a page's rail, whose groups sit under the h1. The content under the header is not raised a level; a heading inside it goes one below through a HeadingLevelProvider.

## When to use it

- **CollapsibleHeader** for a titled block the reader may not need: provenance, counts, derivation, reference notes. On a page, a collapsible [Section](?path=/docs/layout-section--docs) (`isCollapsible`) is the same header with the Section's count, description and action; in a rail of facts, [Inspector.Group](?path=/docs/patterns-inspector--docs).
- **Not** a subtle Button with a chevron as the trigger: it sits outside the outline and its chevron does not turn. **Not** a native `<details>`: its marker and motion are the browser's.
- **Not** for a coordinated set where opening one closes another: that is an [Accordion](?path=/docs/components-accordion--docs). **Not** for a row that discloses more of itself: Item's `isCollapsible` and Table's disclosure column own their chevrons.

## Content

- The header names what is inside, as a noun: "Provenance", "Derivation", "Reference notes"; not "Show more" or "Details" when a more exact word exists.
- A count of what is inside goes in the header as a [Count](?path=/docs/components-count--docs), so the reader knows what opening it shows before they do.
- What the reader needs to act is never only inside a closed block: a warning, a missing prerequisite or an error stays in view.
- The header's words stay the same open and closed; the chevron shows the state.

A warning inside a closed block is read only by someone who opens it: keep it in view above the block.

## Accessibility

Base UI owns expanded state, trigger/panel association, disabled behavior and keyboard activation: Tab reaches the trigger, Enter and Space toggle it, and focus stays on it. CollapsibleHeader's trigger is a button inside a heading, so the block is in the heading outline and its state is announced ("Provenance, collapsed, button"); the chevron is decoration, turned by the same state rather than by colour. Under reduced motion the chevron turns without moving and the content opens without the fold. Retained closed panels stay hidden and unfocusable. `hiddenUntilFound` lets supported browser find-in-page reveal closed content. Nested disclosures keep independent state, and each folds on its own measured height: a Collapsible inside an open Accordion item eases open instead of snapping to the item's settled height.

## Props

The parts expose native Base UI props, refs, `render`, state classes and styles, and a cancellable `onOpenChange`. Content uses the measured `--collapsible-panel-height` for Ledger motion, through its own `--ds-collapse-height` so an ancestor disclosure's height never reaches it, and respects reduced motion. It clips only while it folds: settled open, its overflow is visible, so the focus ring of a link or a button at its edge shows whole. CollapsibleHeader passes its props, its ref and `render` to the trigger; its children are the title.

### State selectors

The Root carries `data-open` and `data-closed`; the trigger carries `data-panel-open` while its content is open. Style a trigger's own chevron from the trigger (`group-data-panel-open/…`), not from `data-open`, which the trigger never has, and never from Radix's `data-state`.

Item's disclosure, a collapsible Section, Inspector.Group and DataTable's Metrics are built on the same Base UI Collapsible; a Stepper step's details are a Collapsible placed in it.
