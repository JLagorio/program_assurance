# Banner

A message about the whole site, at the top of the screen in the shell's Banner area: the loss of data or a function, or something site-wide that changes what the reader can do. One at a time, never dismissible, gone when no longer true. On a bar 42rem wide or more it is one line; narrower, on a phone, the message wraps and the bar grows with it. The action is one link or button drawn in the banner's own colour. The kit's inline message is the [Alert](?path=/docs/components-alert--docs).

An Alert is about the record; a Banner is about the site. Feedback after an act is a toast. If the message would be true for one reader and not the next, it is not a banner.

## Anatomy

| Part    | What it is                                                                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bar     | At least 48px, `dimension.layout.banner`, the tone's bold fill, `space.200` inside at each end; its content centred on a wide bar, from the start on a narrow one.    |
| Icon    | The tone's icon at `dimension.icon.small`: Info, TriangleAlert, CircleAlert, on the first line's centre. `icon` replaces it.                                          |
| Message | `font.body` medium in the inverse text colour: one line on a wide bar, cut with an ellipsis and its whole text as its title when it must be; wrapped on a narrow one. |
| Action  | One link or button after the message's last word, underlined, in the banner's own text colour.                                                                        |

## Variants

Banner has one appearance; the tone is what varies, and there are three.

| Tone          | Use                                                                                                      |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| `information` | Something changed for everyone: the catalogue moved to a new revision, a maintenance window is booked.   |
| `warning`     | The default. Something is about to change what the reader can do: the audit window closes, uploads lock. |
| `danger`      | Something is lost: the connection to the evidence store, the session's writes. Announced at once.        |

There is no success banner and no neutral one: a banner is gone when it is no longer true, and good news is feedback, which is a toast. The kit has the bold fill only, no low-contrast form, since a banner is by definition the one thing on the screen that outranks the page.

Where it lives: `Shell.Banner` is the area, above the top navigation. It holds the Banner and pushes the page down by the banner's height while one is rendered; see [Shell](?path=/docs/layout-shell--docs).

## Sizes

One: the width of the screen. The bar is its own container, so its width, not the window's, decides the form. From 42rem it is one 48px line. Narrower it wraps: `space.100` above and below, the icon on the first line, the action after the last word, and the bar as tall as its lines. `Shell.Banner` measures it, so the top navigation, the side navigation and the panel sit under a banner that wraps.

## States

Present or absent. A banner is rendered while its condition holds and unmounted when it stops; there is no dismissed state, no hover, and no collapsed form. Its action has the kit's focus outline.

## Modifiers

- **`tone`** as in Variants; `warning` when unsaid.
- **`action`** for the one link or button: an anchor, a button, or the router's Link. The Banner colours it and underlines it; it keeps its own `onClick` or `to`.
- **`icon`** to replace the tone's icon with a more specific one, rarely.
- **`className`** for the shell's layout, not for colour.

## Content

- **One sentence: the fact and what it changes.** "The audit window closes in three days; evidence uploads lock after that."
- **Present tense, plain.** No "Please note", no "Attention".
- **The action names where it goes:** "See what changed", "Ask for an extension". One.
- **Not feedback, not a greeting, not a record.** Those are a toast, nothing, and an Alert.

## Style

| Element | Token                                                                                                                                           |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Bar     | `dimension.layout.banner` 48px, the minimum · `color.background.<tone>.bold` · `space.200` inline · `space.100` gap and, wrapped, block padding |
| Text    | `font.body` medium · `color.text.inverse`, `color.text.warning.inverse` on warning                                                              |
| Icon    | `dimension.icon.small` 14px in the text colour                                                                                                  |
| Action  | Underlined, `radius.xsmall` for its focus outline                                                                                               |

The bold fills are Badge's bold appearance, so a danger banner and a danger bold Badge are the same red.

## Accessibility

- **A danger Banner is `role="alert"`**, announced at once; the rest are `role="status"`. The shell's Banner area is a region named "Banner".
- **Nothing is hidden on a phone:** the message wraps there. On a wide bar a message too long for its line is cut for sighted readers only, and its whole text is the message's title; a screen reader hears it all. Keep it to one sentence so everyone gets the same message.
- **The action is in the tab order; the banner is not.** It sits first in the page, before the top navigation, so it is the first thing a keyboard reader meets, which is the point.
- **The bold fills pass 4.5:1** with the inverse text in both modes; the contrast test covers them.

Action focus rings inherit the banner’s contrasting text color, keeping the ring visible against every bold tone.

## Props

Native `div` props and refs target the outer message. IDs, ARIA, data attributes, styles and handlers are forwarded; `className` merges with the default layout. The default role remains `status`, or `alert` for danger. An explicit `role` or live-region attribute controls delivery when the enclosing page needs different announcement behavior.

The `action` keeps its own element, ref, ID, attributes, styles and handlers while receiving the banner’s action classes. A root click handler receives the action’s bubbled click. Default icons are decorative.
