# Kbd

Keyboard input displayed as a keycap, in text, tooltips and menu hints. Use `KbdGroup`
to show the keys of a shortcut together. The existing `Kbd.Group` alias also works.

<Canvas of={Stories.KbdMatrix} />

## Anatomy

Both parts render native `<kbd>` elements and accept their native props and refs.
`Kbd` draws a 16px-tall cap, at least 16px wide, using the sunken surface, default
border, extra-small radius and small text tokens. `KbdGroup` spaces its caps 4px apart.

```tsx
import { Kbd, KbdGroup } from "@ledger/design-system";

<KbdGroup>
  <Kbd label="Command">⌘</Kbd>
  <Kbd>K</Kbd>
</KbdGroup>
```

Use separate caps when that makes a multi-key shortcut easier to read. Choose the
platform's keys in the calling application. There is no platform detection or shortcut
handler inside these components.

## Accessibility

`<kbd>` marks up keyboard input. Caps and groups have no built-in focus or activation
behavior; the surrounding button or menu item owns the action. Keep the action's name
in the surrounding text, such as “Press Command K to search.”

Use `label` to supply a glyph's `aria-label`; an explicit `aria-label` takes precedence.
Screen-reader handling of glyphs and labels varies, so the shortcut should remain
understandable from its visible text and context.

## Props

`className`, `style`, attributes, events and `ref` target each part's own `<kbd>`.
Both refs use `HTMLElement`. Parts expose `data-slot="kbd"` and `data-slot="kbd-group"`.

## Migration

Existing `Kbd`, `label`, and `Kbd.Group` callers need no edits. Native attributes and
refs are now supported on both parts; use the flat `KbdGroup` export for new compositions.
Geometry and token styling are unchanged.
