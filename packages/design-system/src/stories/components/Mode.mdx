# Mode switch

The colour mode is an attribute on the root: `data-color-mode="light"` or `"dark"` pins it, and no attribute lets `prefers-color-scheme` decide. Every token flips by itself, so nothing else changes. The choice is per browser, in `localStorage` under `ledger.color-mode`, never per account.

## Three parts

| Part           | Does                                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modeScript`   | A string for the document head. It applies the stored choice before the first paint so nothing flashes. `modeScriptFor(key)` for a custom storage key.                                                                      |
| `ModeProvider` | Owns the choice. On mount it reads storage and applies it (a no-op after the script); every change is stored and applied at once. `useMode()` returns `{ mode, setMode, resolved }`, where `resolved` is what is on screen. |
| `ModeSwitch`   | The three-state control: light, dark, system. Icons only in chrome, `showLabels` in a settings form. `value` and `onChange` override the provider.                                                                          |

## Wiring it

Plain HTML: put the script in the head, above the stylesheet.

```html
<script>
  (function () {
    try {
      var m = localStorage.getItem("ledger.color-mode");
      if (m === "light" || m === "dark") document.documentElement.dataset.colorMode = m;
    } catch (e) {}
  })();
</script>
```

A framework with a `head()` hook (TanStack Start, Remix) renders the same string inline:

```tsx
import { modeScript, ModeProvider, ModeSwitch } from "@ledger/design-system";

head: () => ({ scripts: [{ children: modeScript }] });
// …
<ModeProvider>
  <Shell>
    <Shell.TopNav>
      …
      <Shell.TopNav.End>
        <ModeSwitch />
      </Shell.TopNav.End>
    </Shell.TopNav>
    …
  </Shell>
</ModeProvider>;
```

Do not also pin `data-color-mode` on the root in markup: the pin wins over the script and the switch cannot move it. Put `suppressHydrationWarning` on the `<html>` element: the script marks it before React hydrates, and React would otherwise report the mismatch.

## Density

Row density is the same shape: `data-density="compact"` on the root resolves `dimension.row` to its compact value (36px instead of 40px), so every table follows and no table takes a density prop. `densityScript` goes in the head beside `modeScript`; `DensityProvider` owns the choice under `ledger.density`; `DensitySwitch` is the two-state control, beside the mode switch in chrome. A table that is compact by design sets `data-density` on its own frame instead.
