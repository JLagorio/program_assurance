# Select

Choose predefined values with shadcn's Base UI Select parts. Ledger supplies control geometry, menu styling, locale direction and Field integration. Use Combobox when the list needs filtering.

```tsx
const statuses = { draft: "Draft", review: "In review" };

<Field>
  <FieldLabel htmlFor="select">Status</FieldLabel>
  <Select name="status" items={statuses} defaultValue="draft">
    <SelectTrigger id="select" className="w-full">
      <SelectValue placeholder="Choose a status" />
    </SelectTrigger>
    <SelectContent>
      <SelectItem value="draft">Draft</SelectItem>
      <SelectItem value="review">In review</SelectItem>
    </SelectContent>
  </Select>
</Field>;
```

## Composition and states

Root owns selected values, open state, form props and modality. Trigger owns native button props, refs, render composition, layout and size: `default` is 32px and `sm` is 28px. It fits its contents by default; use `className="w-full"` in a form or native `style` for a fixed width. Value owns the placeholder and displayed value.

Supply Root's `items` label map/array, object-value label conversion, or Value's children to format the selected value. Item children alone do not label the closed trigger. A label can contain the same Dot or Badge shown on the record. Group and Label identify sections; Separator divides them.

`disabled` prevents interaction and omits the value from submission. `readOnly` keeps the value submitted and the trigger focusable while preventing selection. Item's `disabled` state prevents activation but remains reachable with arrows. For decorated option children, provide Item's plain-text `label` for typeahead. Classes, styles, render props and refs follow each Base UI part's native contract.

## Forms and selection

Connect FieldLabel to Trigger with `htmlFor`/`id`; put `aria-describedby`, `aria-invalid` and `aria-required` on Trigger. Root’s `required` enables native constraint validation. Native form props (`name`, `form`, `autoComplete`, `inputRef`) belong on Root. Root’s ID supplies the default trigger ID; an explicit Trigger ID takes precedence. `inputRef` targets the hidden form input.

Single selection accepts a value or `null`; `onValueChange(value, details)` can reject a change with `details.cancel()`. Cancellation preserves the value, but an item activation still closes a single-select popup. Add a `null` item when the reader needs to clear from the list. Value's placeholder appears when no value is selected.

`multiple` uses arrays and keeps the list open while toggling options. FormData contains one entry per selected value under the same name. Object values can supply `itemToStringLabel`, `itemToStringValue` and `isItemEqualToValue` for display, submission and identity. Root preserves generic single/multiple inference; Item and Value use the installed Base UI value contracts.

With installed Base UI 1.7, form reset is caller-owned: reset controlled values in the form's `onReset`. The example covers required values, cancelled changes, multiple numeric values and object identity.

## Positioning and scrolling

Content includes Portal, Positioner, Popup, List and both scroll arrows. It defaults to trigger width, a 144px minimum, bottom/center placement, a 4px side offset and zero alignment offset. Native style/className/render/ref props target Popup; `finalFocus` controls focus return.

Following shadcn, `alignItemWithTrigger` defaults to true: when space and input modality allow it, the selected item overlaps and aligns with the trigger value. Side/alignment offsets apply in fallback positioning or when `alignItemWithTrigger={false}`. Existing consumers explicitly retain below-trigger placement with that setting. Content's `dir` overrides inherited positioning direction as well as text direction.

The inner List owns bounded scrolling so hover arrows work in both alignment modes with Base UI 1.7. ScrollUpButton and ScrollDownButton wrap Base UI's hover scroll arrows, including their native props and refs. They appear when scrolling is available and are omitted for touch input. Content includes them automatically; the example composes them directly for custom list geometry.

## Accessibility and dialogs

Trigger is a native button with combobox semantics, expanded state and a listbox association. Options announce selected and disabled state. Enter, Space and ArrowDown open; arrows, Home and End move focus; typing matches labels; Enter/Space select. Closed single-select typeahead changes the selected value. Keep a visible Field label or an explicit accessible name on Trigger. Name Content’s list with `aria-label` or `aria-labelledby` when a specific list name is needed. These name the listbox as well as passing through to Popup.

Base UI coordinates nested Select and Dialog popups; Vaul Drawer retains its own portal boundary. Escape dismisses Select before the dialog, returning focus to the trigger. Closing the dialog then returns to its opener.

## Migration and API

Replace the configured root with Select, SelectTrigger, SelectValue and SelectContent. Move trigger refs, ARIA, size, styles and event handlers to Trigger; replace `width` with native style and `small`/`medium` with `sm`/`default`. Move the placeholder to Value. Replace compound Item/Group/Separator with flat exports and put SelectLabel inside SelectGroup. Supply labels through `items` or Value; handle nullable single values explicitly.

The implementation follows [shadcn Select](https://ui.shadcn.com/docs/components/base/select) and [Base UI Select](https://base-ui.com/react/components/select), using the installed Base UI version. Content adds shadcn's five positioning props to Popup; Ledger adds token styling and locale/Field/dialog integration.
