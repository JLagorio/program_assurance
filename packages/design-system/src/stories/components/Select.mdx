# Select

**Status: Stable.**

Choose one value, or a few, from a short list the reader does not need to search, with shadcn's Base UI Select parts. Ledger supplies the control geometry, the menu styling, locale direction and the Field binding.

```tsx
const statuses = { draft: "Draft", review: "In review" };

<Field>
  <FieldLabel>Status</FieldLabel>
  <Select name="status" items={statuses} defaultValue="draft">
    <SelectTrigger>
      <SelectValue placeholder="Choose a status" />
    </SelectTrigger>
    <SelectContent>
      <SelectItem value="draft">Draft</SelectItem>
      <SelectItem value="review">In review</SelectItem>
    </SelectContent>
  </Select>
</Field>;
```

## When to use it

Use a Select for a fixed set of four to a dozen values the reader recognises on sight: a status, a priority, a kind, a revision. The choice table under [Forms](?path=/docs/patterns-forms--docs) decides between the choice controls:

- Two or three options the reader should compare at a glance are a [RadioGroup](?path=/docs/components-radiogroup--docs), which shows every option at once.
- A long list, or records the reader finds by typing a name or an identifier, is a [Combobox](?path=/docs/components-combobox--docs).
- An on/off setting is a [Switch](?path=/docs/components-switch--docs) or a [Checkbox](?path=/docs/components-checkbox--docs).
- Actions and view options behind a button are a [DropdownMenu](?path=/docs/components-dropdownmenu--docs), never a Select whose change runs a command.

## Composition and states

Root owns the selected value, the open state, the form props and modality. Trigger owns the native button props, refs, render composition, layout and size, on the control scale Input, Combobox and Button share: `medium` is 32px, the default, and `small` is 28px, for a toolbar or a dense row. `data-size` says the same word, so InputGroup's rule keyed on `small` finds a small Select. `sm` and `default` are the deprecated shadcn spellings, kept for one version and renamed by `ledger/no-deprecated-name`. Value owns the placeholder and the displayed value.

Supply Root's `items` label map or array, object-value label conversion, or Value's children to format the selected value. Item children alone do not label the closed trigger. A label can contain the same Dot or Badge shown on the record. Group and Label identify sections; Separator divides them.

`disabled` prevents interaction and omits the value from submission. `readOnly` keeps the value submitted and the trigger focusable while preventing selection. Item's `disabled` prevents activation and stays reachable with the arrow keys. For decorated option children, give Item a plain-text `label` for typeahead. Classes, styles, render props and refs follow each Base UI part's native contract.

Inside a [Field](?path=/docs/components-field--docs) the trigger fills the Field, as Input and Combobox do. Elsewhere (a toolbar, a filter row, a rail) it fits its value. Either way it never grows past its container: a value longer than the room truncates inside the trigger, and the whole value is in the open list. A class or style width on Trigger wins.

## Positioning and scrolling

Content includes Portal, Positioner, Popup, List and both scroll arrows. The list opens below its trigger, or above it where there is no room below, from the trigger's start edge with a 4px gap. It is at least as wide as the trigger (and at least 144px, `dimension.part.select`), and as wide as its longest option up to the 720px measure and the room in the viewport; past that an option wraps inside its row, including an unbroken identifier or digest, and never runs under the check mark. Near the edge of the window the list shifts back so it stays whole. Native style, className, render and ref props target Popup; `finalFocus` controls focus return.

`alignItemWithTrigger` opts into the list that opens over its trigger with the chosen option on the value, where space and the input device allow it. Use it only for a compact trigger whose list is short, since it covers the field's label and the fields around it; the side and alignment offsets apply only when it falls back to opening below. Content's `dir` overrides the inherited positioning direction as well as the text direction.

The inner List owns bounded scrolling so the hover arrows work in both placements. ScrollUpButton and ScrollDownButton wrap Base UI's hover scroll arrows, with their native props and refs, and wear the [Scroller](?path=/docs/components-scroller--docs) arrow look across the popup's inner box. They appear when the list can scroll and are omitted for touch input. Content includes them; the example composes them directly for a custom list geometry, beside the standard Content in right to left.

## Descriptions and disabled reasons

`description` on SelectItem adds a second line under the option, in smaller subtle text that wraps inside the list: what tells two similar options apart ("287 controls for a moderate-impact system"). The line is the option's accessible description, not part of its name, so typeahead finds the label alone and the closed trigger shows only the label.

An option that cannot be chosen takes `disabledReason` instead of `disabled`: the option is disabled, the arrow keys still reach it, a screen reader announces it as unavailable and reads the reason, and the reason shows as its description line, readable on the faded row. Write what would make it available. A tooltip cannot do this job in a list, and a disabled option without a reason leaves the reader guessing. A list where most options are unavailable is the wrong control; say what is missing beside the field instead.

## Forms and selection

Inside a [Field](?path=/docs/components-field--docs) the FieldLabel names the trigger and the open list, the hint and error describe the trigger, and the Field's `invalid`, `required` and `disabled` reach it, with no ids. Clicking the label opens the list, as clicking the trigger does, because the trigger is a button the label activates. Outside a Field, connect a label to Trigger with `htmlFor` and `id`, and put `aria-describedby`, `aria-invalid` and `aria-required` on Trigger. Root's `required` enables native constraint validation; the Field's `required` only announces. Native form props (`name`, `form`, `autoComplete`, `inputRef`) belong on Root. Root's id supplies the default trigger id; an explicit Trigger id takes precedence. `inputRef` targets the hidden form input.

Single selection accepts a value or `null`; `onValueChange(value, details)` can reject a change with `details.cancel()`. Cancellation keeps the value, and an item activation still closes a single-select popup. Add a `null` item when the reader needs to clear from the list. Value's placeholder appears when no value is selected.

`multiple` uses arrays and keeps the list open while the reader toggles options. FormData holds one entry per selected value under the same name. Object values supply `itemToStringLabel`, `itemToStringValue` and `isItemEqualToValue` for display, submission and identity. Root keeps generic single and multiple inference; Item and Value use the installed Base UI value contracts.

With Base UI 1.7, form reset is caller-owned: reset controlled values in the form's `onReset`. The example covers required values, cancelled changes, multiple numeric values and object identity.

## Content

- A visible FieldLabel names the Select. The placeholder is never its only name: once a value is chosen the placeholder is gone, and nothing would say what the field is.
- The placeholder says the action and the noun: "Choose a status", "Choose a revision". It never says "Select…", "Optional" or repeats the label; the Field marks a required field.
- Option labels are short nouns in sentence case, the words the record shows. Put the difference between two similar options in `description`, not in a longer label.
- Order options by meaning (the workflow order of statuses, severity from high to low), and alphabetically only when they have no order of their own.
- A "No status" option is a `null` item at the end, after a separator, and only where clearing is allowed.

## Accessibility and dialogs

Trigger is a native button with combobox semantics, an expanded state and a listbox association. Options announce their selected and disabled states. Enter, Space and ArrowDown open; the arrow keys, Home and End move focus; typing matches labels; Enter and Space select. Closed single-select typeahead changes the selected value. Keep a visible Field label or an explicit accessible name on Trigger. Inside a Field the list is named by the label; name Content's list with `aria-label` or `aria-labelledby` where another name is needed. These name the listbox as well as passing through to Popup.

Base UI coordinates nested Select, Dialog and Drawer popups. Escape dismisses the Select before the dialog and returns focus to the trigger; closing the dialog then returns to its opener.
