# Alert

**Status: Stable.**

An inline message about a record or a region: what happened, what it means, and the way out. It stays where it is while it is true, beside the content it is about.

<Canvas of={Stories.Playground} />

## Choosing between them

| The message                                     | Part                                                      |
| ----------------------------------------------- | --------------------------------------------------------- |
| About this record or region, while it holds     | Alert                                                     |
| About one field of a form                       | [FieldError](?path=/docs/components-field--docs) under it |
| Several problems with a submitted form          | [ErrorSummary](?path=/docs/components-errorsummary--docs) |
| About the whole site, for every reader          | [Banner](?path=/docs/components-banner--docs)             |
| Feedback after an act that needs nothing more   | A [toast](?path=/docs/components-toaster--docs)           |
| A decision the reader must take before going on | [AlertDialog](?path=/docs/components-alertdialog--docs)   |

## Anatomy

```tsx
<Alert variant="danger">
  <AlertIcon />
  <AlertTitle>Import failed</AlertTitle>
  <AlertDescription>The file is missing record identifiers.</AlertDescription>
  <AlertAction>
    <TextLink href="#format">Read the required format</TextLink>
    <Button size="small">Try the import again</Button>
  </AlertAction>
</Alert>
```

| Part               | What it is                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `Alert`            | The region, in the tone's subtle fill. An svg as its first child (AlertIcon) takes a column of its own.                                         |
| `AlertIcon`        | The tone's icon: Info, CircleCheck, TriangleAlert or CircleAlert, the same glyphs as Banner and the toast list. `icon` replaces it. Decorative. |
| `AlertTitle`       | What happened, in medium weight. An unbroken code or hash wraps inside it.                                                                      |
| `AlertDescription` | What it means or what to do, one or two lines.                                                                                                  |
| `AlertAction`      | The way out: a TextLink to where it is fixed, or a small Button that fixes it. Links are underlined here as in the title and the description.   |

Content and icons are the caller's. Actions stay in normal flow under the message, so a long recovery link fits a narrow panel.

## Variants and states

`tone` is the Ledger meaning and picks the fill, the icon and the default role. `variant` is shadcn's treatment: `default` is the neutral tone and `destructive`, or its Ledger spelling `danger`, the danger tone; a `tone` overrides either.

## Content

- **The title says what happened** in the reader's words: "Import failed", "Records could not be refreshed". Not "Error", not the server's message.
- **The description says what it means or what to do**, in one or two lines. A server message is detail: put it after the plain sentence, or leave it out.
- **One way out**, named for where it goes or what it does. A link navigates; a small Button acts.
- **No Alert for a result the reader did not ask about.** Feedback after an act is a toast.

## Accessibility

The role follows the tone, and `role` overrides it:

| The message                                                     | Role                                 |
| --------------------------------------------------------------- | ------------------------------------ |
| A failure after the reader's act, which stops the task          | `alert`, the danger tone's default   |
| A result or an update the reader should hear when idle          | `status`, every other tone's default |
| Standing guidance that is read in place (a permission, a draft) | `note`                               |
| Said already by the page's own live region                      | `role={undefined}`, none             |

An Alert rendered with the page is not a change, so it is not announced whatever its role; the role matters when it appears after an act. Name it with `aria-labelledby` on its title when a screen reader should meet it as a landmark-like region. AlertIcon is hidden from assistive technology. On every tone's fill the icon and the focus ring hold 3:1, and a TextLink 4.5:1 in the standard modes; under increased contrast the neutral fill darkens, and the link holds 4.5:1 on the status tones only. The contrast test checks each pair. In forced colours the fill is replaced, so the Alert keeps a CanvasText edge and its icon.

## Don't

An Alert says what happened in its title and offers the way out as one small action beside it, never a red bar with the server's words and a page-wide button under it. A standing note is `role="note"`, read in place, never a danger Alert that interrupts the page when nothing failed.
