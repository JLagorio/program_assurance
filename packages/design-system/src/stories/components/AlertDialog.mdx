# AlertDialog

**Status: Stable.**

A decision that needs a word before it happens: delete, archive, discard a draft. Built on [Base UI Alert Dialog](https://base-ui.com/react/components/alert-dialog) with [shadcn’s composition](https://ui.shadcn.com/docs/components/base/alert-dialog) and Ledger's tokens.

<Canvas of={Stories.ConfirmationAndPending} />

## When to use it

- **Before a destructive or irreversible command**, or before throwing away a draft.
- **Over the Dialog or Sheet that owns the decision**, the one stack overlays allow.

Not for a form: that is a [Dialog](?path=/docs/components-dialog--docs). Not for a result the reader only needs to know about: that is a toast or an [Alert](?path=/docs/components-alert--docs). Not for a question the reader can undo in one step: do it, then offer Undo.

## Anatomy

- **AlertDialogHeader** holds an optional AlertDialogMedia, the title (the question, an h2, a [Heading](?path=/docs/primitives-heading--docs) at `overlay`, 15/22 medium) and the description (the consequence).
- **AlertDialogBody** holds what the decision affects when one line is not enough: the records a delete removes, a field for a reason. It follows the header with its inset and no divider, and scrolls between the header and the footer so the answers stay in view.
- **AlertDialogFooter** holds AlertDialogCancel, the safe answer, before AlertDialogAction, the verb, on the dialog's own surface below a hairline.
- AlertDialogContent records the overlay surface as the current one; AlertDialogPortal and AlertDialogOverlay are exported for a custom popup.

## Widths

`width` on AlertDialogContent picks a step, in [Dialog](?path=/docs/components-dialog--docs)'s words for Dialog's widths, so a `small` alert dialog is as wide as a `small` dialog. Do not set pixels in `style`.

| `width`  | Size               | For                                                    |
| -------- | ------------------ | ------------------------------------------------------ |
| `xsmall` | 320px              | A one-line question                                    |
| `small`  | 400px, the default | A question and its consequence                         |
| `medium` | 520px              | A decision whose AlertDialogBody lists what it affects |

Every step keeps a `space.200` gutter on each side of the window, so on a phone the popup is the phone's width less the gutter. `size` is the deprecated spelling: `size="sm"` is `width="xsmall"` and `size="default"` is `width="small"`; `ledger/no-deprecated-name` rewrites the prop and its value in one fix.

## Pending

`pending` on the AlertDialog holds it while the command runs: Escape and AlertDialogCancel are cancelled, Cancel is disabled but stays focusable (`aria-disabled`), since focus starts there, and the popup is `aria-busy`. Give the Action `isLoading`, which keeps its focus, and close with `open={false}` when the command succeeds. On a failure, end the pending state and say inside the dialog what went wrong, with the Action as the retry. The Action never closes the dialog by itself; render it as an AlertDialogCancel (`render={<AlertDialogCancel />}`) only when the verb needs no command to finish first.

## Accessibility

- **The role is `alertdialog`**, named by the title and described by the description.
- **The blanket never dismisses it**; Escape and Cancel do, unless it is pending. A press on the blanket leaves focus where it was.
- **Focus goes to Cancel** when the decision is destructive: pass it as `initialFocus`. Focus returns to what opened the dialog, recorded as it opens, or to `finalFocus` when that went away.
- **Over a Dialog or Sheet**, render it inside the parent's content: Base UI draws no second blanket for it, and the parent dims under it instead, so the prompt stands apart in both modes.
- **Forced colours keep the edge**: the popup draws a CanvasText outline.

## Content

- The title is the question: "Delete 24 drafts?". The description is the consequence, not the question again: "These drafts are removed for everyone." A record's name or code in the title wraps rather than running past the edge; a failure's cause goes in the body, through an Alert.
- The Action says the verb ("Delete drafts"); Cancel says the safe way out ("Keep drafts", "Keep editing").

## Props

AlertDialog takes Base UI AlertDialog's root props, `open`, `defaultOpen`, `onOpenChange` (with the change's `reason` and `cancel()` in its details), `onOpenChangeComplete`, `actionsRef` and `handle`, and Ledger's `pending`; it has no `modal` or `disablePointerDismissal`, since an alert dialog is always modal and ignores the blanket. AlertDialogContent takes the popup's `initialFocus`, `finalFocus`, `render`, `className` and `style`, and Ledger's `width`. Every part takes its element's native attributes, and its `data-slot` comes after them, so a caller's attribute never renames the part (Native attributes, below). The title, the description and AlertDialogCancel are the exception: another part renders as them through `render` (a PageHeader.Title as the title, an AlertDialogAction as Cancel) and its `data-slot` names the element, as it does on a Button. The types are in [Base UI's API reference](https://base-ui.com/react/components/alert-dialog#api-reference).
