# Textarea

**Status: Stable.**

Several lines of free text: a note, description or implementation statement. This follows shadcn's native textarea implementation with Ledger styling.

## When to use it

- **Authored text of more than one line**: a description, a rationale, an implementation statement, a review note, a comment that is part of a form.
- **Text whose line breaks matter**: a statement whose paragraphs a [Prose](?path=/docs/components-typography--docs) block shows as written.

Not for one line, a name or a title: that is an [Input](?path=/docs/components-input--docs). Not for a comment or a message the reader sends, with suggestions as they type: that is a [Composer](?path=/docs/patterns-composer--docs). Not for one authored value edited where it is shown on a record: that is an [Editable](?path=/docs/patterns-editable--docs)'s multiline text. Not for code or a configuration excerpt shown to the reader: that is a [CodeBlock](?path=/docs/components-codeblock--docs).

## Content

- The label, the hint and the error are the Field's, in its words ([Field](?path=/docs/components-field--docs), Content).
- The hint says what the text is for and who reads it ("Explain the evidence supporting this decision"); a length the text must keep to is `characterLimit`'s count, not a sentence in the hint.
- `rows` is the length of the answer expected, so the box's height says how much to write: two lines for a note, four for a description, eight for a narrative.
- A placeholder is an example of the opening words, or nothing; never the label or an instruction.

## Anatomy

```tsx
<Field invalid={invalid} required>
  <FieldLabel>Review note</FieldLabel>
  <Textarea name="note" value={note} onChange={(event) => setNote(event.target.value)} rows={4} />
  <FieldDescription>Explain the evidence supporting this decision.</FieldDescription>
  <FieldError errors={errors} />
</Field>
```

Textarea is a native textarea on Base UI's Field.Control, so a [Field](?path=/docs/components-field--docs) binds it as it binds Input: label, hint and error with no ids, and the Field's `invalid`, `required` and `disabled`. It keeps the native textarea's props, events and ref.

## Variants and states

`rows` is the expected answer length and the box's height in lines: two for a note, four for a description, eight for a narrative, three by default. The reader can drag the box taller. Read-only is the sunken surface with a dashed edge and no hover; disabled and invalid use the shared control styling. A value that is never edited where it is shown is a [KeyValue](?path=/docs/components-keyvalue--docs), not a read-only Textarea. Use InputGroupTextarea when the editor has header or footer addons.

`autoResize` grows the box with its text, from `rows` lines up to `maxRows`, where it scrolls, so a long statement or rationale is read without dragging a corner. The browser sizes it (`field-sizing: content`) where it can, and the Textarea measures it where it cannot. InputGroupTextarea takes both props.

## Length

`characterLimit` is a soft limit. A count under the box says how many characters are left, and past the limit how many too many, in the danger colour with the box's edge; the text stays whole, so a pasted statement never loses its tail. The count describes the box (with "Up to 2,000 characters." for assistive technology), is announced when the reader pauses typing, and fails native validation with its own words; the form's schema check on submit says what fixes it. Use it instead of `maxLength`, which cuts a paste off without a word. Put the limit in the count, not in the hint.

## Accessibility

In a Field the label, hint, error, invalid state and requirement reach the textarea without ids. Outside one, use a label with `htmlFor` and the textarea’s `id`, `aria-describedby` for hints, and `aria-invalid` and `aria-required` explicitly. Keep labels and instructions visible. Native keyboard editing, selection and form submission remain available.

## Props

`TextareaProps` is the native textarea contract, including `ref`, `rows`, `name`, `value`, `defaultValue`, `onChange`, `onBlur`, `required` and ARIA attributes, plus `autoResize`, `maxRows` and `characterLimit`. Ref and event targets are HTMLTextAreaElement. It takes Input's API as well: `onValueChange(value, details)` beside the native `onChange`, `render` to replace or compose the element (which forwards its props and ref to a textarea), and `className` and `style` as a value or a function of the control's state (`focused`, `dirty`, `touched`, `valid`, `disabled`). With `characterLimit` the Textarea renders the count after the box, so the box and its count are siblings in the Field.
