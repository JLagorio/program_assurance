# ScrollArea

A bounded region that scrolls with the kit's own bar, which the reader can see and drag, on [Base UI ScrollArea](https://base-ui.com/react/components/scroll-area) in shadcn's ScrollArea and ScrollBar composition.

Use it where the bar itself is the cue: a list in a resizable pane, a wide timeline in a card. A region with nothing to add scrolls with native overflow; a list or a strip that needs an arrow at each edge that can still scroll is a [Scroller](?path=/docs/components-scroller--docs). An overlay's scrolling content is its Body part (DialogBody, SheetBody), never a ScrollArea. [Choosing a part](?path=/docs/guidance-choosing-a-part--docs) has the whole table.

## Anatomy

`ScrollArea` renders the root, the viewport that scrolls, a vertical `ScrollBar` and the corner. Add `<ScrollBar orientation="horizontal" />` as a child for a region that scrolls sideways; overflow decides which bars show. Put sizing classes (a height, a maximum width, a border and radius) on `ScrollArea`.

## Accessibility

- **Keyboard.** The viewport is a tab stop while it overflows, so the arrow keys, Page Up and Page Down scroll it; a region that fits adds no stop. Base UI manages the bar's geometry and dragging.
- **A name.** Name the region through `viewportProps`, with `role="region"` and an `aria-label` that says what scrolls ("Evidence list").
- **Focus.** The root clips, so the viewport's focus ring is drawn inside it, following the root's corners.
- **Direction** follows LedgerProvider or an explicit `dir`, for the layout and the bar alike.
- **Forced colours.** The thumb is drawn in `CanvasText`, and `Highlight` under the pointer, so it stays visible when the system replaces the tokens.

## Props

`viewportProps` takes the viewport's native attributes and its ref: the element that actually scrolls, for a name, a role or a virtualizer. The root takes Base UI's ScrollArea props, including `render` and state-based `className` and `style`. ScrollBar takes `orientation` and `keepMounted`.

### Migration and API

- Replace `label` with `viewportProps` holding `role="region"` and `aria-label`. Put sizing classes on ScrollArea.
- Replace a root `orientation="horizontal"` or `"both"` with a horizontal ScrollBar child; overflow determines which bars are needed.
- The bar visibility shortcut and fixed hide delay are gone. Base UI's state attributes (`data-hovering`, `data-scrolling`) style the bar when needed.
