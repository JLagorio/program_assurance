# Toaster

Short feedback after an action. Mount Toaster near the application root and call `toast.success("Evidence linked")` from the workflow. Sonner owns the stack, timer, swipe and live region.

## Anatomy

Each toast contains a message, optional description and icon, and optional action, cancel or close buttons. Ledger supplies token styles, localized labels and direction.

<Canvas of={Stories.Playground} />

## Variants and states

Use plain, success, info, warning or error messages. The error helper defaults to eight seconds with a close button; other normal toasts default to four seconds. Explicit per-toast options override those defaults.

Actions can undo a completed operation. Questions and destructive confirmations belong in AlertDialog.

<Canvas of={Stories.WithAction} />

Loading and promise toasts stay while work is pending. A promise replaces its pending message with the resolved or rejected outcome.

<Canvas of={Stories.Working} />

## Accessibility

Sonner supplies the notification region, keyboard shortcut and focus behavior. Ledger provides the localized region and close labels. Override `containerAriaLabel`, `hotkey` or `toastOptions.closeButtonAriaLabel` through Sonner's native props when appropriate. Essential record state belongs in persistent page content.

## Props

<ArgTypes of={Toaster} />

Toaster accepts all installed Sonner props and its native HTMLElement ref: position, duration, visibleToasts, gap, offsets, theme, direction, icons, toastOptions, styles and more. Defaults remain bottom-right, four visible toasts, 8px gap and 16px offset. Token colors follow Ledger's active theme. At narrow widths, the stack is bounded by Sonner's native mobile offsets in either direction; toasts fill that space unless a per-toast width overrides it.

Partial icons, toastOptions styles and per-part classNames preserve unspecified Ledger defaults. A supplied classNames entry replaces that part's default classes. Other native props take precedence over defaults.

<Canvas of={Stories.NativeOptions} />

### Migration

Existing Toaster calls keep working. Options previously blocked by the wrapper can now be passed directly. If multiple stacks are needed, give each an `id` and target it with `toast(..., { toasterId })`. The examples use separate IDs so they can coexist on this page.
