# Toaster

Short feedback after an action. This family follows shadcn's Base UI Toast implementation, with Ledger surfaces, typography, motion and localized labels.

## Anatomy

Mount one Toaster near the application root. It composes ToastProvider, ToastPortal, ToastViewport and a stack of Toast / ToastContent / ToastTitle / ToastDescription / ToastAction / ToastClose parts. The default stack is at the bottom end edge, bounded on narrow screens.

```tsx
<Toaster />;
// After the provider mounts, from a workflow:
const id = toast.add({ title: "Evidence linked", type: "success" });
toast.update(id, { description: "Bank reconciliation, July" });
toast.close(id);
```

## Variants and states

Set `type` to success, info, warning, error or loading for the standard icons. Toaster defaults to a 4000ms timeout and four visible toasts. Set `timeout: 0` for persistent feedback. Application errors explicitly use 8000ms; the native manager does not infer timeouts from type.

<Canvas of={Stories.Playground} />

Supply `actionProps` with `children` and `onClick`. The action does not close automatically: call `close(id)` when it should dismiss. This lets an action update a toast or keep it visible while work continues.

`promise` replaces loading feedback with the resolved or rejected result and returns a promise with the original value. Await or handle its rejection as usual.

## Accessibility

Base UI owns announcements, timers, stack focus and swipe dismissal. F6 focuses the notification viewport; Shift+Tab from that viewport returns to the previous element. Hover and focus pause timers. Each default toast includes a localized Close button. Loading icons are decorative because the toast already announces the work.

Keep essential record state in persistent page content. Toast portals participate in Base UI popup accessibility, including while a dialog is open.

## Props

Toaster accepts native Provider props: `children`, `timeout`, `limit` and `toastManager`. It is state-only and has no DOM ref. For custom placement or presentation, compose the exported parts; ToastViewport owns native div props/ref, direction and accessible name. Styled parts retain native `render`, refs and class/style state callbacks. `createToastManager` isolates stacks, and `useToastManager` reads the nearest provider's toasts and actions.

<Canvas of={Stories.NativeOptions} />

Migration: replace `toast.success(message, options)` with `toast.add({ title: message, type: "success", ...options })`; use `close` instead of `dismiss`, `timeout` instead of `duration`, zero instead of Infinity, and `actionProps.children` instead of `action.label`. The callable Sonner adapter and Sonner Toaster options are removed. Independent stacks use separate managers. A manager must have a mounted provider before feedback can be shown.
