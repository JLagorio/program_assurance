# Card

A raised container for a table, chart, form or set of facts. Compose its header, content and footer as needed.

## Anatomy

```tsx
<Card>
  <CardHeader>
    <CardTitle>
      <h2>Evidence</h2>
    </CardTitle>
    <CardDescription>Three linked artifacts</CardDescription>
    <CardAction>
      <Button size="small">Add evidence</Button>
    </CardAction>
  </CardHeader>
  <CardContent>Assessment details</CardContent>
  <CardFooter>
    <Button>Save</Button>
  </CardFooter>
</Card>
```

CardHeader arranges the title, description and optional action. CardContent supplies the inset. CardFooter holds actions or secondary content. The root records its raised surface so sticky table headers remain opaque.

## Variants and states

The default size uses Ledger's standard inset; `size="sm"` reduces the header, content and footer spacing. Tables and charts that own their spacing can sit directly inside Card. Loading, empty and error behavior belongs to the content.

## Accessibility

All parts are native divs. CardTitle does not choose a heading level: compose an h2 or h3 when the card should appear in the document outline. Existing callers retain their h2 headings. Name a region with `role="region"` and `aria-labelledby` when a landmark is useful. Links and buttons inside the card keep their own semantics and focus.

### Migration

Replace `Card.Header title/description/action` with CardHeader containing CardTitle, CardDescription and CardAction. Replace `Card.Body` with CardContent. Add a heading inside CardTitle to preserve the original outline. Card now lives in the components layer; application imports still come from the package root.
