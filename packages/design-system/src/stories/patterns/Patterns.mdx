# Pages

The two page archetypes and the parts they are assembled from.

**IndexPage** is a header, one filter row, one dense table. The inline detail surface is the PreviewRail, opened from the eye in a Table.Id cell; the record itself is never inline.

<Canvas of={Stories.Index} />

**ShowPage** is a RecordHeader, one tab strip running full width, then the tab body. The rail renders only beside the overview tab; every other tab is full width and self-contained. The rail column is `dimension.layout.rail`.

| Part | Does |
| --- | --- |
| **PageHeader** | Eyebrow, title on `font.heading.medium`, one line, actions on the right. |
| **RecordHeader** | Back chevron (`back` takes a link element), id and meta, title, actions, `facts` for the strip of Facts under the title (at most six; the rest go in the rail), and `below` for a persistent state strip. |
| **Section** | A titled region with a rule under its heading. Prefer Block for work and Collapsible for reference. |
| **Card** | A framed block on the raised surface, with an optional header row. It records its surface so a sticky table header inside it stays opaque. |
| **Related** | A small card of linked records with a count and rows that may be buttons. |
| **Empty** | A dashed frame with a title, one line of why, and the action that fills it. |
| **PreviewRail** | The right rail as a preview of a row, never the record itself. |
| **PreviewSheet** | The peek panel: a Sheet that previews a row over the page. Its header is the compact RecordHeader: the Preview eyebrow with the id and one `status`, the title, the meta line, at most three `facts`. The footer's first item opens the full record, more `links` follow, `actions` sit on the right. `onBack` when it is one frame of a stack. |
| **PickerSheet** | Choosing many from hundreds: search and filters in a toolbar that does not scroll, a Table with Table.Selection in the body, a footer that counts the chosen rows and names the one action. A second frame of the same sheet fills in per-row fields. |
| **PageSkeleton** | The page before its data: a title, a tab strip, rows. |

## Rail or sheet

Both preview a row and leave the list in place; neither is the record. The **rail** goes beside an IndexPage table that leaves room for it, opened from the eye on the id. The **sheet** goes over a full-width table (a tree, a board), and wherever the preview carries actions, opened from the row. A page uses one or the other, never both.

## The hover ladder

Three rungs, each one deeper than the last, and a record reads the same on every rung because the same parts draw it.

1. **Hover on an id or a name is a glance.** A HoverCard: facts only, no actions. It opens on focus too. Program and risk ids do this today.
2. **Click is the peek.** The PreviewSheet: the compact header, the facts, and the actions that make sense without leaving. A record opened from inside a peek is the next frame of the same sheet; the back chevron and the browser's back are the same thing when the stack lives in the URL.
3. **The footer link is the record.** The page, where the work is done. The preview never grows into it.

One preview body per record type, at two densities (glance, peek), rendered by the kit's three shells (HoverCard, PreviewSheet, PreviewRail). Which body a record type gets is the app's.

## Choosing many

When the question is "which of these many belong on this one" and the many are found by attribute rather than by name, the picker is a PickerSheet, not a Combobox. Frame one chooses: search and filters that stay put, a sortable Table with Table.Selection, a selection that survives search, a footer that counts. Frame two, when the chosen rows need fields of their own, shows them as a compact table with Editable cells and a defaults row applied to all; the back chevron keeps the selection. The kit owns the frame; the caller owns the columns, rows and selection. The spec is `docs/superpowers/specs/2026-09-02-picker-sheet.md`.
