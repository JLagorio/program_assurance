# Toolbar

**Status: Stable.**

The row above a table: search first, saved views next, filters after them, and display controls and actions at the end. Everything in it is the small size, so the row is one height and the table starts right under it. A [DataTable](?path=/docs/patterns-data-table--docs) takes it as `toolbar`, above its frameless rows; a plain [Table](?path=/docs/components-table--docs) puts it above, `space.200` apart as the DataTable does, so the table's sticky header never covers the ring of a focused control in the row.

It is a row of controls, not a heading. A standalone register has a PageHeader; an embedded register can use a Section. Toolbar contains controls only.

## Anatomy

| Part    | What it is                                                                                                                                                                                                                      |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Search  | A small [SearchField](?path=/docs/components-searchfield--docs), up to 240px (`dimension.part.search`), named by its placeholder, with a clear button while it holds a query. Only with `onSearch`.                             |
| Views   | `views`, after search: saved-view controls that never fold into More; a strip wider than its space scrolls inside it, arrows at the edges where a pointer can hover.                                                            |
| Filters | `filters`, after saved views: [FilterChips](?path=/docs/components-filterchip--docs), a [ToggleGroup](?path=/docs/components-togglegroup--docs) of lenses, a small Select that narrows.                                         |
| Display | `children`, before the actions: Columns, Settings, a grouping Select, an overflow of collection commands. They fold into More after the filters.                                                                                |
| More    | The one overflow: a small Button, "More", that appears only when something has folded. Its popover holds the filters, then the display controls under a divider. With `activeFilters`, it counts the folded filters that apply. |
| Actions | `actions`, pushed to the end: small Buttons with the primary last, or a count as text, "12 of 340 controls". They never fold.                                                                                                   |

## Variants

Toolbar has one appearance. What varies is which parts the register needs:

| The register                       | Use                                                                                                                                |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Searched, filtered, acted on       | Search, chips, actions.                                                                                                            |
| Seen through lenses                | No search; a ToggleGroup in `filters`, a count at the end.                                                                         |
| One thing to choose about the view | A small Select in `children`.                                                                                                      |
| A yes or no about the rows         | A [FilterChip](?path=/docs/components-filterchip--docs) toggle (`isActive`) in `filters`.                                          |
| Which rows there are to ask about  | A small Select in `views`: a revision, an edition or a scope. It never folds, because it changes what every other control acts on. |
| Only a count or an Export          | `actions` alone.                                                                                                                   |
| Rows chosen for a batch action     | Not a Toolbar: the DataTable's SelectionBar takes the Toolbar's place in the table's `toolbar` slot while rows are chosen.         |

There is no title in a Toolbar, no tall Toolbar (the kit's rows are one height and so is the row above them), and no collapsed search that opens from an icon: a register that is searched shows its field.

## Sizes

One height: every control in the row is small, `dimension.control.small` 28px, so a Button and a SelectTrigger in it say `size="small"`. The caller owns surrounding spacing.

The toolbar measures its container, not the window, so it responds the same in a panel as on a phone. When the row cannot hold everything it folds instead of stacking. `filters` move into More first; if the row still cannot hold the display controls (`children`), they follow, under a divider, and each still opens its own menu from inside More. A choice that closes a menu opened there closes More with it, as a parent menu would; a toggle, a submenu, or an item that keeps its menu open keeps More open. The search, the saved views and `actions` never fold, and the primary keeps its whole label.

When search, views, More and the actions still cannot share one row, the row wraps into two in the same order: the search with the saved views, then More with the actions at the end. Every register takes the same two rows at a given width, a views menu keeps its label, count and chevron, and the primary keeps its whole label. The toolbar stays at two rows while More and the primary fit side by side; narrower than that, as in a panel at its minimum width, the actions take a line of their own under More, still at the end, and nothing overlaps. The search gives up room first, down to 128px; below that, the saved views take what is left: a views menu shortens its label with an ellipsis, its full label in its title, and keeps its count and chevron, and a strip of several views scrolls. A toolbar without a search stays one row, and actions that do not fit wrap inside their group, labels whole: another reason to keep to five. While More is open it keeps what it holds, even if its container widens; the row takes everything back when it closes. A filter the reader changes inside More is measured again as More closes, so a label that shrank there lets the filters back into the row when they now fit.

## States

The toolbar has no states of its own; its controls have theirs. The search field is empty (the placeholder names what is searched), typed, or focused, and the table under it narrows on every keystroke. A DataTable says the result once the reader stops typing, filtering or paging ("8 of 24 tasks", "No matching tasks") through the page's announcer. Over a plain Table the caller says it: a count at the end in a polite `role="status"`, as in Live, or `announce()`.

The search is live, so Enter does nothing: a toolbar inside a form, as in a dialog that links the records a reader picks, never submits the form when the reader presses Enter to search. The clear button and Escape empty the search through `onSearch("")` and keep focus in it; with the search empty, Escape reaches the dialog or popover around the toolbar.

## Modifiers

- **`search`, `onSearch`, `placeholder`**: the field, its value, and what it searches. Without `onSearch` there is no field. The clear button and Escape call `onSearch("")`.
- **`defaultSearch`**: the first query when the toolbar owns it. Pass `onSearch` without `search` and the field keeps what the reader types; pass `search` to own the query.
- **`views`**: saved-view controls immediately after search. They never fold.
- **`filters`**: filters, after saved views. The first to fold into More.
- **`activeFilters`**: how many filters apply. While they are folded, More counts them and names the count.
- **`children`**: display controls, such as grouping, columns, settings and an overflow of collection commands. They fold into More after the filters.
- **`actions`**: what sits at the end. They never fold.
- **`className`** for a frame's own padding; inside a DataTable the frame gives it.
- **Native div props and a ref** reach the row: an `id`, `data-` attributes, and a role with a name where the row is the page's search (`role="search"` with an `aria-label`). The row keeps its own `data-slot`.

## Content

- **The placeholder names what is searched**: "Search controls", "Control or title". Not "Search…".
- **Filters are nouns**: Owner, Status, Gaps.
- **Up to five actions**; more go under a More menu. The primary last.
- **A count reads "12 of 340 controls"**, tabular, `font.body.small` in `color.text.subtle`. It is text, not a Badge or a Count.

More's own words come from the locale, like the other labels the kit writes; the caller writes the placeholder, the filters and the actions in the reader's language.

## Accessibility

- **A plain row, not the ARIA `toolbar` role.** That role promises arrow-key movement between its controls; a row of a search field, chips and buttons is better served by Tab in reading order, so Toolbar renders a plain layout div.
- **The search field is named** by its placeholder through `aria-label`; the icon is decorative. Its clear button is named "Clear search" and is not a Tab stop, since Escape does the same; see [SearchField](?path=/docs/components-searchfield--docs).
- **Focus stays visible** on every control in the row, the saved views included: the views strip draws a focused control's ring inside itself.
- **The result is said, not only shown.** A DataTable announces it after a search, a filter or a page; over a plain Table the caller's count at the end is a polite status (States).
- **The chips say pressed**; a chip that opens a popover says expanded. See FilterChip.
- **Order:** search, saved views, filters, display controls, actions. The reader narrows first and acts last, and Tab follows. Two rows are the same order wrapped, so Tab and a screen reader read the same sequence at every width.
- **More says what it holds**: "More filters", "More display options" or "More filters and display options", and with `activeFilters` how many of the folded filters apply: "More filters, 2 applied". Its popover is a dialog named by its title: Filters, Display, or Filters and display; below filters, the display controls are a group named Display. Each name is a locale message (`moreFilters`, `moreDisplay`, `moreFiltersAndDisplay`, `moreFiltersApplied`, `moreFiltersAndDisplayApplied`, `filters`, `display`, `filtersAndDisplay`, and `more` for the visible label), so a `LedgerProvider` translates them. It uses ordinary Tab navigation, so nested filters and menus keep their own behavior. Escape closes one layer at a time: an inner menu first, back to its trigger, then More, back to More.
- **Focus never falls to the page.** A control that folds while it has focus hands it to More; when More goes away, focus moves to the first control that came back. Closing More returns focus to it, unless the reader has moved on, as into a dialog that a command in More opened.

## Don't

Every control in the row is the small size, up to five actions sit at the end with the primary last, and the primary goes in `actions`, never as a child beside the search, a default-size Button among small ones, or seven actions in a row.
