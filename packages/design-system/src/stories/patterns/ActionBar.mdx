# ActionBar

The record's header pinned above the work: the trail ending in the id, the title with a word of context, the state axes as facts under it, and the actions that change them, with the tab strip below. It is a [RecordHeader](?path=/docs/patterns-recordheader--docs) with two rules of its own. The first state is the headline, a Badge, and the rest read as a dot and a word, so one thing on the bar is coloured. And a blocked action stays in the row, disabled, with its reason written under it, because hiding the action hides the rule. The actions sit beside the title, as on every record's header. It heads a work surface, a control being implemented, a package being submitted, and the detail of a [WorkPane](?path=/docs/shapes-workpane--docs).

## Anatomy

| Part    | What it is                                                                                                                       |
| ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Trail   | The parents as `crumbs`, then the id as the current crumb: the way back.                                                         |
| Title   | The record's name, the h1, with the `context` after it in a few words: the scope, the owner.                                     |
| Actions | At the end of the title's line: one primary, the rest secondary. A blocked one disabled, its reason under the row.               |
| States  | Facts under the title, above a rule: the label and the state. The first a Badge; the rest an Indicator; a control when it may be changed. |
| Tabs    | The strip under everything, running the full width.                                                                              |
| Bar     | Sticky under the shell's header, on the page's surface, a rule under it.                                                         |

## Variants

ActionBar has one appearance. What varies is what it carries:

| Bar               | Use                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| States and actions | A control being worked: assessment and evidence as states, request and mark as actions.        |
| Every action blocked | A package that cannot be submitted: the primary disabled and the reason under it.             |
| With a control    | A state the viewer may change: the owner as a button, the value in its place.                    |
| With the trail and tabs | The page's header: the parents, the id, and the sections under the bar.                    |

Not built, and why: a menu for the actions past two, because a bar with more than two verbs is a page with a wrong job; a tooltip for the blocked reason, because a disabled button takes no hover and no focus and the reason is read by everyone under the row; a state axis as a pill each, because then nothing is the headline; a bar that is not sticky, because the actions are the point and they stay in reach.

## Sizes

One size, the RecordHeader's: the title `font.heading.small`, as wide as the page. The bar is as tall as its lines: the trail, the title, the states, the tabs.

## States

| State           | What changes                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Allowed         | The button live.                                                                                |
| Blocked         | The button disabled and the reason under the row: "Submit: 7 findings still open".              |
| Pinned          | The page scrolled: the bar stays under the shell's header, the work scrolls beneath.             |

## Modifiers

- **`crumbs`**, **`id`**, **`title`**, **`context`**, **`states`**, **`actions`**, **`tabs`** as in Anatomy. `breadcrumb` is deprecated: pass the parents as `crumbs`, the id is the last crumb.
- **A state** is `label`, `value`, `tone`, and `control` when the viewer may change it.
- **An action** is `label`, `onSelect`, `primary`, and `blocked` with the reason.

## Content

- **The context is a few words**: the scope and the owner, "Atlas payments platform · Dana Whitlock". Never a sentence.
- **A state is an axis and a word**: "Assessment: Partially satisfied", "Evidence: 34d". Two or three axes; the first is the one the reader decides by.
- **An action is a verb**: "Request evidence", "Mark satisfied", "Submit". One primary.
- **A reason says what would unblock**: "2 findings still open", "already verified". Not "Not allowed".
- **The trail ends with the id**, the title is the name, as on every record.

## Style

| Element | Token                                                                                                             |
| ------- | ----------------------------------------------------------------------------------------------------------------- |
| Bar     | Sticky at the shell's header · `elevation.surface.current` · `color.border` under · `space.050` above · `space.150` below without tabs |
| Header  | RecordHeader: trail, `font.heading.small` semibold title, `font.body.small` subtle context, `space.150` between the rows |
| States  | Fact.Group · `color.border` rule above · Badge xsmall for the first · Indicator for the rest                       |
| Actions | Button, one primary · `space.100` between · the reasons `font.body.xsmall` `color.text.subtle`, `space.050` under, end-aligned, wrapping within `dimension.layout.measure` |
| Tabs    | The Tabs strip, full width, under the states                                                                       |

## Accessibility

- **The title is the page's `h1`**, read with the context; the trail is a `nav` named "Breadcrumb" before it, ending in the id as the current page.
- **The states are terms and values**, read in order after the title: "Assessment, Partially satisfied".
- **A blocked action is a disabled button with its reason as text beside it**, so a screen reader hears the reason without hovering; a disabled button is skipped by Tab, and the reason is not.
- **The bar stays in view**, so the actions are one Tab away from the work at any scroll.
- **A control in a state is a button named by its value**, "Dana Whitlock", with the label read before it.
