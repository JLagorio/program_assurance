# Composer

**Status: Stable.**

A shared text composer for messages, comments and other short drafts. Ledger owns keyboard completion, submission progress and recovery. The consuming application owns recipients, permissions, persistence, suggestion identity and serialized text. Owner: Ledger maintainers; consumers own their adapters.

<Canvas of={Stories.ComposerMatrix} />

## When to use it

- **A comment on a record**: the Composer sits at the top of the record's Comments section, above the [Timeline](?path=/docs/components-timeline--docs) that lists them newest first. Its `label` names the record ("Comment on this task") and `submitLabel` the action ("Comment"). A send that lands clears the draft and keeps focus in the field for the next one; a rejected send keeps the draft, and its `errorMessage` says whether sending again could post it twice.
- **A short message or note** that is written and sent where the reader is, with no other fields to fill.

Not for a record's fields or a longer form with more than the text: that is a Dialog with a Textarea in a Field. Not for a value edited in place: that is [Editable](?path=/docs/patterns-editable--docs).

## Anatomy

A named textarea, optional leading marker, contextual fields above, instructions below, optional `actions` before the buttons (a second thing to do with the draft), optional cancel action, and primary submission action. Suggestions float under the field in the kit's positioner; a rejected send puts its message under the field.

## Variants

One composition, with optional suggestion and leading slots. No event taxonomy or built-in mention syntax. The example below uses a `#` adapter and stable topic identifiers to demonstrate a non-person use case.

## Sizes

Three initial textarea rows. The layout follows its container. The suggestion list is 280px wide and at most 240px tall, bounded by the width and the height the window leaves; it scrolls when taller. It is portaled, so a panel, dialog or card that clips its content cannot cut it, and it opens above the field where the window ends below it. Long option labels truncate visually while retaining their accessible text.

<Canvas of={Stories.SuggestionsAtTheEdge} />

Inside a Dialog, Sheet or Popover the list belongs to that overlay: choosing an option leaves it open, and Escape closes the list before the overlay.

## States

Empty drafts cannot submit. Nonempty drafts submit with the button or Ctrl/⌘ + Enter. While pending, the textarea is read-only and repeat submission and cancellation are blocked. Fulfillment clears the submitted draft and returns focus to the field for the next message; rejection retains the draft with its message under the field. A newer controlled draft is retained when an earlier request resolves. A disabled composer cannot be edited or submitted.

## Modifiers

`value` and `onValueChange` select caller-owned state; `defaultValue` supplies an uncontrolled initial draft. Do not switch ownership while mounted. `ref`, `id`, and `name` target the visible textarea. `leading`, `hint`, `children` and `actions` are rendered slots; `actions` sits before the cancel and primary buttons, for a secondary Button the caller wires to the draft it keeps through `value`.

`getSuggestions(text, caret)` returns UTF-16 replacement offsets and ordered options, or null. The caller provides unique option IDs, accessible labels, exact insertion strings, filtering and result limits. Invalid ranges are ignored. The adapter is synchronous; fetching remote candidates belongs to the caller. No rich-text document model is implied.

`errorMessage` is the message after a rejected send, or a function of the rejection that returns it, to show the server's reason.

## Content

Supply a descriptive `label` independently of placeholder text. `submitLabel`, `cancelLabel`, `suggestionsLabel`, `errorMessage` and `hint` default to the LedgerProvider's messages (Send, Cancel, Suggestions, "Could not send. Try again." and "Ctrl/⌘ + Enter to send"), so a translated provider translates them; pass your own words where the task names its action, such as Comment. The default keyboard hint is left out on a touch screen (a coarse primary pointer), which has no key to press it with; `hint={null}` shows none anywhere. Use stable identities when your product serializes references; a display name need not be an identity. Resolve `onSubmit` only when your application's promised save boundary succeeds; throw or reject on failure.

## Style

Textarea and Button provide the control styling. Layout uses `space.100`; suggestions use the overlay surface, default border and overlay shadow, and the active option `color.background.neutral.subtle.hovered`. In forced colours the active option is Highlight with HighlightText. Pending and error states remain understandable without animation or color alone.

## Accessibility

The textarea keeps focus while suggestions are navigated, and has `aria-haspopup="listbox"`, `aria-autocomplete="list"`, `aria-controls` and `aria-activedescendant` while the list is open. Up/Down selects an option, Enter or Tab inserts it, Shift+Tab leaves the field and closes the list, and Escape closes the list without dismissing a containing overlay. Because Tab inserts while the list is open, the list says so when it appears: a polite announcement gives the count and the keys ("2 suggestions. Up and Down to choose, Enter or Tab to insert."), and each move names the option and its place ("Delivery, 2 of 2"). IME confirmation does not insert or submit. Suggestions expose listbox and option semantics. Pointer selection returns focus to the textarea. Instructions and a rejected send's message describe the textarea, and the rejection is also announced at once. After a send lands, focus returns to the textarea, since Send is unavailable with an empty draft. The completion key handling and save recovery run in both color modes and in forced colours.
