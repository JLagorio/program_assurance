# RecordHeader

The head of a record page: a breadcrumb trail ending in the current record's id, followed by its title, short meta, and actions. Parent links provide the way back. Put record details in the page's rail and page-level tabs in [ShowPage](?path=/docs/patterns-pages--docs).

<Canvas of={Stories.RecordHeaderMatrix} />

## Anatomy

| Part      | Responsibility                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------------ |
| `crumbs`  | Parent `BreadcrumbItem` elements, with separators between them. The header supplies the navigation and list. |
| `id`      | The unlinked current crumb, appended after the parents. With no parents, it forms the whole trail.           |
| `title`   | The record's name in an `h1`, under the trail. Long titles wrap.                                             |
| `meta`    | A short label or Badge after the title, inside the same heading. Long meta truncates.                        |
| `actions` | Controls beside the heading, in the order supplied by the caller.                                            |
| `below`   | Optional content after the header rows, such as a lifecycle Stepper or an ActionBar.                         |

Omit both `crumbs` and `id` for a heading without a trail. Empty parent fragments or arrays also work; an id-only trail has no visible leading separator.

<Canvas of={Stories.EmptyParentLevels} />

## Usage

- Use the record's name as the title, matching its list entry: “Atlas payments platform” or “Encrypt telemetry in transit.”
- Keep meta brief: a status Badge, a baseline, or “Updated 2h ago.” It appears after the title, not after the id.
- Use one primary action and at most two accompanying controls; put additional actions in a menu. The header preserves caller order.
- Put owners, dates, and other details in the rail's Inspector. The legacy `facts` slot remains available while callers migrate.
- Pass parent links as `crumbs` and the current record identifier as `id`. On a sub-page, the trail can include a link to its parent record.
- Use ShowPage's `tabs` for a tab strip spanning the page. `below` remains available for a local strip and renders the content supplied to it.

## Layout

The title uses `font.heading.small` (20px/26px) with semibold weight. Meta uses `font.body.small` and `color.text.subtle`. The current id inherits the breadcrumb's body-small font and uses `color.text`.

The header fills its container. Its rows have `space.100` gaps; the heading and actions are separated by `space.150`, with `space.100` between actions. Title and meta can wrap onto another line. Actions keep their intrinsic width, so use a menu when the available space is limited.

## Accessibility

- The title and meta share the page's `h1`; use concise text that makes sense when announced together.
- The generated trail is a `nav` named “breadcrumb,” before the heading. Its current id has `aria-current="page"` and is outside the tab order. Parent links are focusable.
- Give action controls accessible names and arrange them in the desired reading and keyboard order; RecordHeader does not reorder them.
- Content passed to `below` keeps its own semantics and interaction behavior.

## Migration

Three deprecated props remain in the API:

| Prop         | Current behavior                                                              | Replacement                                                                 |
| ------------ | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `facts`      | Still renders a `Fact.Group` below the title, with a top border and padding.  | Move details into the page's rail.                                          |
| `breadcrumb` | Renders the supplied content as-is, taking precedence over `crumbs` and `id`. | Pass parent items through `crumbs` and the current identifier through `id`. |
| `back`       | Ignored; no back control is rendered.                                         | Use the parent links in the breadcrumb trail.                               |
