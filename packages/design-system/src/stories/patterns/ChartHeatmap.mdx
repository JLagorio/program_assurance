# Heatmap

**Status: Stable.**

A grid of rows by columns with a value painted in each cell: how much, across two dimensions. One hue from light to dark for a magnitude; two hues around grey for above and below; or the status tones by place, which is the risk matrix. It is a table, in the markup as on the page, so a screen reader reads it as one and the keyboard walks it. `Chart.Scale` is its key. It lives in a [Chart](?path=/docs/patterns-chart-overview--docs) Frame.

## Anatomy

| Part    | What it is                                                                                                                                                                                                                                                                   |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cell    | `radius.xsmall`, 2px from its neighbours, its fill the value's step on the scale; a faint step (one close to the surface) adds a `color.border.bold` edge. With `zeroStep`, a zero is `color.chart.track`. A cell with no value is a dashed edge with no fill and no number. |
| Value   | Printed in the cell on a status scale (the tone's text on its fill); on a colour scale a screen-reader-only text, or with `showValues` the number on an `elevation.surface` chip.                                                                                            |
| Headers | Column names across the top, row names down the side, in `font.body.xsmall` and `font.body.small`; the corner names the rows. With `columnHeadings="vertical"` a column's name reads up the page from its column.                                                            |
| Scale   | `Chart.Scale`: the five steps in a row with the ends or the thresholds named, the midpoint's word on a diverging one, or the status tones with their words. Under the grid, `space.150` away.                                                                                |
| Tooltip | The cell's title: row, column, value.                                                                                                                                                                                                                                        |
| Card    | On a chosen cell: the row and column, the value, then the caller's facts.                                                                                                                                                                                                    |

## Variants

| Variant              | Use                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scale="sequential"` | How much: findings by family and month, in `color.chart.sequential.1` to `5`. The default.                                                                                                                                                                          |
| `scale="diverging"`  | Above and below a `midpoint`: schedule variance in days, red below and blue above around grey.                                                                                                                                                                      |
| A tone function      | Status by place: the risk matrix, each cell the tone its position earns, the count printed.                                                                                                                                                                         |
| `showValues`         | The value printed on a colour scale too, when the reader must read every cell: on a surface chip in `color.text`, since text never sits on a chart colour. Unsaid, a Frame around the grid offers the reader a Values toggle that prints them; `false` offers none. |

## Sizes

| `size`   | Cell height | Where                                                         |
| -------- | ----------- | ------------------------------------------------------------- |
| `small`  | 24px        | Many rows: families by month in a rail.                       |
| `medium` | 32px        | A Section. The default.                                       |
| `large`  | 40px        | A five-by-five matrix that is a page's point, values printed. |

A cell is at least 40px wide, and every value column takes the widest heading's width, so a long heading does not make its column look weighted. Past the width it has, the grid scrolls sideways inside its own box with the row names held at the start; while it overflows the box is a named region and a tab stop, so a keyboard can scroll it. In a Frame's expanded Dialog the cells are `large`.

<Canvas of={Stories.Narrow} />

## Long column names

On one line, a heading makes every value column as wide as the longest name. Where the names are long and the cells hold a digit or two, that width goes to the names: fourteen techniques take three times the room their counts need, and the grid scrolls sideways over cells that are mostly space. `columnHeadings="vertical"` turns each heading to read up the page from its column, so a column is as wide as its cells and the names take height instead, once, above the grid.

<Canvas of={Stories.VerticalHeadings} />

Use it for names that have no short form and that, on one line, would make the grid scroll. Where the vocabulary has a short form its readers know (a family's code, a month), head the columns with that, and keep `horizontal` while the grid fits: a turned name is slower to read. Each heading stands over its own column, so under the row names of a grid that still scrolls, on a phone, a hidden column's name is hidden with it. Where the page reads right to left the headings turn the other way, its mirror.

A name longer than a heading's line, about twenty-five characters, takes a second line beside the first, and the columns keep their width; a name that needs a third line widens every column alike. Keep to names of a few words.

## States

| State    | What changes                                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hover    | The cell's title as a tooltip.                                                                                                                                                                                                  |
| Chosen   | With `onSelect` or `details` the cells with a value but zero are buttons (`selectable` says which otherwise): a click, Enter or Space chooses one, it takes the focus ring, the others dim, and the card opens on it.           |
| Linked   | With `link` the cells with a value but zero are the links it returns (`selectable` says which otherwise): the register filtered to the cell's row and column. A link takes the focus ring and navigates; it never opens a card. |
| Loading  | Every cell in `color.skeleton`, pulsing, at the grid's size. The Frame sets it from `state="loading"`.                                                                                                                          |
| Isolated | Not applicable: a heatmap has no series to hide.                                                                                                                                                                                |

<Canvas of={Stories.Details} />

A cell that opens a register is a link, not a button: `link` returns the link element for a cell (a router's Link, or `<a href>`) and the cell becomes it, so a modifier or middle click opens a new tab. Both axes are levels in words, in the order given, so a risk matrix lists likelihood from the top and impact across. The table twin's values link to the same places.

## Rows in a hierarchy

<Canvas of={Stories.GroupedRows} />

Where the rows hold other rows (a system and its elements, a division and its teams), give them in the hierarchy's order and say each row's depth with `rowLevel`: its name is indented under the row that holds it, three levels at most. `summary` marks the rows that total the rows under them. A summary row prints its numbers with no fill, so a total is never read as one more step of the scale, and the grid reads as its lowest rows with their totals above them. The caller owns the totals: the grid draws the value it is given for every row.

A status function may return a tone with `emphasis: "bold"`, the tone's solid fill, for the one level that must not read as its neighbour: critical beside high, where both are danger. Keep it to one level, and name it on the key with the same `emphasis`.

## Modifiers

- **`scale`**, **`domain`**, **`midpoint`**, **`showValues`** as in Variants.
- **`rowLevel`** and **`summary`** as in Rows in a hierarchy.
- **`zeroStep`** gives zero a step of its own, so none reads apart from a few. Give the Scale the same. A zero is then quiet: its number is in the cell's title and said to assistive technology, never drawn, so the cells that hold something are the ones a reader sees. On a sequential scale the track-coloured cell is the mark; on a status scale and in a `summary` row it is a faint point with no fill, never the lowest level's tone.
- **`rowLabel`**, **`columnLabel`** name the dimensions: the corner cell, and what a screen reader hears.
- **`columnHeadings`** as in Long column names: `vertical` turns the headings, so a column is as wide as its cells. `horizontal` when unsaid.
- **`format`** for the values, the tooltip, the card and the Frame's table. The Frame's, else the kit's.
- **`onSelect`** and **`details`** as in States; the selection is `{ row, column, value }`. **`selectable`** says which cells choose or link.
- **`link`** returns the link a cell opens, from the same selection, or `undefined` to leave the cell as it is. A cell it links does not also choose.
- **`loading`** draws the skeleton, the grid keeping its rows and columns; the Frame sets it from `state="loading"`.
- **`label`** names the grid, a table; the Frame's title when unsaid. Native props and a ref reach the grid's box, its scroller, and `aria-describedby` describes the table.

## Content

- **A magnitude is one hue.** Never a status tone for a count: nine findings is not "danger".
- **Diverging needs a true midpoint**: zero variance, the plan, last year. Without one the data is sequential.
- **Status by place prints its count**: the tone's text on the tone's fill is the Badge's, already in the contrast test.
- **Name the dimensions**: "Likelihood" by "Impact", "Family" by "Month".
- **The scale's ends are words**: "0" and "12 findings"; "−12 days", "On plan", "+12 days".
- **Give the key the grid's `domain`**, so it prints the value at each step's edge and reads as the grid is binned; the grid's `domain` is the data's own when unsaid, which the key cannot know.
- **A status grid has a status key**: `scale="status"` with each tone and what it means, so the risk level is never carried by colour and place alone.

## Style

| Element        | Token                                                                                                                                                                            |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cell           | `color.chart.sequential.<step>` · `color.chart.diverging.<step>` · or `color.background.<tone>` with `color.text.<tone>` · `radius.xsmall` · 2px apart                           |
| Faint step     | `color.chart.sequential.1` to `3`, `color.chart.diverging.negative`, `midpoint`, `positive` and `color.chart.track` add a 1px `color.border.bold` edge, in the cells and the key |
| Empty          | No fill · a 1px dashed `color.border.bold` edge                                                                                                                                  |
| Headers        | `font.body.xsmall` medium `color.text.subtlest` across, or turned with a line of 160px at most · `font.body.small` `color.text.subtle` down                                      |
| Scale          | Five steps 24 by 8, 32 by 8 with thresholds · `radius.xsmall` · labels in `font.body.xsmall` `color.text.subtlest` · status swatches 12px in the cells' fills                    |
| Forced colours | A cell and a step keep their fill, outlined in `CanvasText`; an empty cell is a dashed `GrayText` box                                                                            |
| Chosen         | `color.border.focused` outline                                                                                                                                                   |
| Dimmed         | `opacity.disabled`                                                                                                                                                               |
| Skeleton       | `color.skeleton`                                                                                                                                                                 |

## Accessibility

- **It is a table**: a `table` named by `label`, column headers across and row headers down, the corner naming the rows and, for a screen reader, the columns ("Likelihood by Impact"). A screen reader reads each cell as "row, column, value".
- **Every cell has its value in text**: printed on a status scale, screen-reader-only on a colour scale, so the colour is never the only channel. In a forced-colours mode a colour-scale cell keeps its fill, outlined, rather than turning to the system background.
- **No cell sinks into the page.** The steps close to the surface fall under 3:1 on it in one mode or the other, so they wear a `color.border.bold` edge, which holds 3:1; an empty cell's edge is dashed and it has no fill, so it never passes for a low value.
- **A colour scale's values are one press away** in a Frame: Values, a toggle button whose name stays "Values" while `aria-pressed` says whether they show, prints every value on its cell for keyboard, touch and magnifier readers alike. The reader's choice holds across the table view and the expanded Dialog.
- **The table twin is the grid pivoted**: the Frame's Table toggle and CSV lay it out as a row per row and a column per column in the grid's order, headed by `rowLabel`, every value printed and no colour.
- **A vertical heading is the same header cell**: its text is whole and where it was in the markup, so a screen reader hears each column's name, and each cell as "row, column, value", as before. For a reader who would rather not turn their head, the pointer over a heading says the name level (its `title`), and so do a cell's title, its card and the table twin, for the keyboard and touch too.
- **Cells that choose are buttons**, focusable in reading order, with the kit's focus ring, each named by its place and value ("Likely, Critical: 3"); a zero is no tab stop unless `selectable` says so. A cell that opens a card says so (`aria-haspopup="dialog"`) and whether it is open (`aria-expanded`). The card is a dialog and focus returns to the cell when it closes.
- **Cells that open a register are links**, named the same way, and the table twin carries the same links, so the reader who reads the numbers as a table can open them too.
- **The words are the locale's**: the cell's title ("SC, Jun: 12", "AU, Apr: none") and the dimensions ("Likelihood by Impact") come from `LedgerProvider` messages.
- **The scale's swatches are `aria-hidden`**: its words are text, and the values are in the cells.
- **Loading is `aria-busy`** and named "[the grid's name], loading".

### Chart.Scale

The key under the grid. `scale="sequential"` or `"diverging"` draws the ramp with `min`, `mid` and `max` as words; given the Heatmap's `domain`, a sequential key prints the value at each step's edge in `format` (the Frame's, else the kit's), `max` replacing the top when it is a word, and `zeroStep` adds zero's swatch before the five. `scale="status"` takes `steps`, each a tone and what it means.

## Don't

A count is one hue from light to dark, never painted in the status tones. A status grid prints its counts on its cells, never leaving the reader to hover each one.
