# Vanta: the end-to-end journey

Fetched: 2026-11-17. Read from 9 help-center articles (8 notes; one URL now redirects): `pages/vanta-grc-implementation-guide.md`, `bringing-your-current-compliance-program-into-vanta.md` (archived 2026-05-18 copy), `best-practices-migrating-your-security-program-to-vanta.md`, `adaptive-framework-scoping.md`, `getting-started-with-workspaces.md`, `getting-started-with-policies.md`, `vanta-agent-guided-flows.md`, `interface-settings.md`, `notifications-and-notification-settings.md`.

Timing, from the implementation guide: 30 days plan → 60 days core buildout ("first passing tests") → 90 days audit-ready ("evidence mapped, risks treated, test coverage achieved") → 6 months audit in progress or complete.

## Stages

1. **Plan**: kick-off call, name stakeholders and roles, pick scoping (workspaces vs. framework segmentation), agree the implementation plan, set user access and notifications. Pages: Settings (User permissions, Roles, Notifications), My Account (Notifications, Interface). Done: plan aligned, owners named for each hub.
2. **Workspaces** (several entities only): the CSM switches Workspaces on; each workspace gets its own company Information, integrations, policies, user groups and IdP; users are added, given a role per workspace and linked. Pages: workspace selector, Workspace console (Home, Users), Settings → Information. Done: Console Home lists every workspace with Controls / Tests / Documents % (inferred as the signal).
3. **Connect**: the empty Home has 1 primary, "Connect identity provider"; then cloud, MDM, source control, ticketing. Pages: Home, Integrations (Available / Connected / Errors tabs). Done: people synced to Users; Errors tab empty and Tests page populated (inferred).
4. **Bring in the existing program**: import controls and a custom framework from Excel templates (upload → Review & finalize → Import), or ask the Vanta Agent to classify files and propose a plan to approve; from another tool, a 12-step migration checklist. Pages: Controls, Frameworks, Vanta Agent, Documents. Done: toasts "Successfully uploaded X controls" / "Framework successfully imported!"; coverage compared with the previous tool.
5. **Scope frameworks**: per framework, switch integrations in or out, deselect single assets, exclude new assets, pick people groups, auto-scope devices with their owner. Pages: Frameworks → framework → Scope tab (Systems / People), Configure scope page, Scope Settings, Inventory (Framework scope column). Done: each integration card reads In scope / Out of scope; audits and tests then filter by scope "with no further action".
6. **Controls and tests**: map tests and documents to each control (AI suggestions with accept/reject, or +), write custom tests, deactivate tests that do not apply, assign owners. Pages: framework record (sections, control side panel), Controls, Tests (OK %, Needs attention: Overdue / Due soon / Needs remediation), test record (Results, Controls, How to remediate, Create task). Done: owners on every test; "Controls OK" and "Tests passing" rise (the guide's first milestone: "first test passes").
7. **Evidence and documents**: upload or link each requested document with an effective date and a recurrence; link documents to controls. Pages: Documents (status "Needs document since …"), document page, Add document to control. Done: evidence mapped (the 90-day outcome); no document left at "Needs document" (inferred).
8. **Policies**: per default policy, use a template / policy builder or import a file; submit to an approver; assign to employee groups for acceptance; renew yearly. Pages: Policies (Overall status, Latest version status, Renew by, Personnel acceptance N/M), policy editor, policy record (Policy versions, Controls). Done: Approved, its policy test OK, acceptance test OK ("first policy approved"); later Renew soon 6 weeks before, Expired after.
9. **People and access**: assign onboarding tasks by group (training, policy acceptance), match people to accounts, run a first access review. Pages: Personnel, People (Remind), onboarding page, Access, Access Reviews. Done: personnel tasks complete; first access review complete.
10. **Vendors and risk**: add vendors with inherent risk; build the risk register (manual, import template, or Risk library → Add); treatment plans and approvals; unfixable vulnerabilities go to the register. Pages: Vendors, Risk (Overview, Risk register, Risk library, Action tracker, Snapshots), Vulnerabilities. Done: every risk has an owner and a treatment plan.
11. **Work loop** (continuous): owners get alerts on what they own (batched every 1–4 h) and digests of counts by area ("6 tests need attention on Tests"), each count linking to its page; reminders run on SLAs. Pages: Notifications settings, email / Slack / Teams, Home (Compliance progress per framework), Tests, My work (in the nav, inferred). Done (inferred): digest counts fall and framework % rises week on week (Console shows "+N% since last week").
12. **Audit**: invite the auditor (Auditor role), share the IRL, create the audit (Framework, External/Internal, audit firm, auditor; "cannot be edited once created"; 3 steps), work outstanding evidence in the Audit View with owners, then archive and plan the next cycle. Pages: Audits → Add a new audit, Audit View, framework record (Audit timeline). Done: audit in progress or complete by month 6; archived with feedback addressed.

## Shapes repeated across the journey

- Register header with 2 summary cards (e.g. Assignment ring + Completion bar; OK % + Needs attention by Overdue / Due soon / Needs remediation), then a filtered table.
- Record pages with a status badge, meta row (owner, source, last refreshed), and count tabs (Tasks (13), Controls (44)).
- Two-pane link pickers: list with "Added" chips, detail with one Add / Remove.
- Import = template → upload → Review & finalize (Clean rows / Rows with issues) → Import → toast + filtered register.
- Multi-step modals say "Step 1 of 3" and explain consequences before the primary.
