## 3. How Vanta helps a user fix things

Counts over the 160 Troubleshooting articles (my keyword count, approximate):

- 27 are titled "Error: …" with the exact message a user sees.
- 24 name a failing test and the fix that passes it.
- 20 are "How to …" procedures.
- 19 end in deactivate or scope out, with a reason and manual evidence.
- 12 end in the device CLI (reset, register, doctor).
- 11 end in Reconnect, never delete.
- 8 say it is a limitation with no fix today.

The pattern, in the order a reader meets it:

1. The rule sits where the failure is: the test's description lists what passes (five metric names); Test criteria answers what, inputs, pass and fail.
2. The failure states its cause in one sentence ("Your load balancers don't have error count monitors set up.") and lists one row per failing resource.
3. Each failing row links to the resource itself (Inventory, search prefilled with "account:region"), so the target of the fix is one click away.
4. "How to fix" / "How to remediate →" is one button in the result's header holding the remediation text; help articles carry the console steps.
5. Integration trouble is told apart from a failed control: Upstream status "Error fetching data", and a list by integration, item and exact error, each with a help link.
6. Every failing item carries a due date from an SLA: a chip on the card, a REMEDIATE BY column, red relative words ("Due about 1 year ago").
7. Re-run is on the page: "Last refreshed about 7 hours ago · Refresh" (manual 15–60 min, automatic within 24 h).
8. Exits that are not fixes stay accountable: deactivate indefinitely or until a date, reason required, evidence optional; a Deactivated tab keeps reason and date; it reactivates itself.
9. Data to debug with: Export test data (CSV), View as JSON + Copy, Out of scope resources.
10. The CloudWatch article checks in order: alarm in the export, metric name column, dimension value, then support with screenshots.
11. Article shapes repeat: "Environment details / Cause / Resolution" for errors; "Likely cause / How to confirm / Fix" per symptom in newer integration guides (Figma, Bitbucket, Dropbox).
12. A scenario table with a "key indicator" column picks the right fix (the IdP duplicate-email error: 3 scenarios, options A–C).
13. Hard cases get an ordered checklist: missing Inspector scans walks 6 checks (reconnect banner, Connected, scope loaded, instance in scope, Inspector toggle, SSM agent state).
14. Self-service diagnostics come before support (vanta-cli reset, register, doctor), then a stated list of what to send (doctor output, manage-bde output, logs, screenshots).
15. Repair keeps state: Reconnect from the Integrations banner; re-adding GCP projects keeps scoping and ownership.
16. The fix goes to whoever must act: a HOW TO FIX column with Send reminder, a bulk reminder, and the employee's own task page.

## 4. For Program Assurance

- SLA categories (hours, days, business days) in Settings, applied to operational issues, assessment findings and POA&M milestones, drawn as Remediate by plus red relative words; extends the DueDate the app already draws.
- Deactivate with a required reason, optional evidence and an until-date that reactivates itself, as the honest form of "not applicable" or a risk acceptance; a Deactivated tab beside each register (vulnerabilities, findings, evidence requests).
- A control's record already has the trace and Next step; add Vanta's three parts above them: the rule's text, the cause in one sentence, the failing objectives or systems one row each, each linked.
- Tell "could not read" from "failed" (Vanta's Upstream status): an evidence source that stopped syncing or expired reads as a data problem, never as a control status.
- A per-user alert matrix (event × Email/Slack, batched every 1 or 4 h) so an owner hears what changed; My work › Attention is its in-app half, Assign owner its trigger.
- Every register's export asks All records or Current filtered view; add a framework-level gap export of the Control status view for an AO or an assessor.
- Evidence versions: the effective date with the computed expiry under it, "Renew before …", draft → submit for approval → accepted, and a friendly filename for the assessor; the Review queue already holds the approve step.
- An audit log register over activity events (Type, Date, Source, Action, Targets, Details sentence, Export CSV) answers who changed what, beside the Portfolio feed.
- A facts row on derived records ("Derived 5 min ago · Refresh", "SLA: 14 days") for posture snapshots and control status reads.
