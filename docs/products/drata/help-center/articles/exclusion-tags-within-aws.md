# Exclusion tags within AWS

Source: https://help.drata.com/en/articles/5260549-exclusion-tags-within-aws
Collection: Understand the Drata Platform › Monitoring
Updated: 2026-08-05
Fetched: 2026-11-22
Description: Implementing exclusion tags for specific resources

## Article text

## Overview

You may have resources within AWS that should always be ignored by Drata's compliance automation tests. Sometimes these are new resources that spin up each day. The exclusion tag functionality will allow you to exclude these resources with a tag within AWS.

## Prerequisite

- [AWS infrastructure connection](aws-integration-guide-infrastructure-user-access-review.md) must be connected to Drata
- Drata must be actively monitoring AWS resources

**Exclusions Tags for AWS: **

Exclusion tags currently apply to the following resource types. Drata will continue to expand the use of exclusion tags.

- RDS instances and clusters
- EKS clusters
- EC2 instances
- S3 buckets
- Security groups
- SQS queues
- IAM users
- ECS (Fargate) clusters and services
- ElastiCache Redis clusters
   - *Note: currently this exclusion is only supported on Test 68 - Customer Data is Encrypted at Rest*
- NoSQL DB (DynamoDB) tables
- Elasticsearch (OpenSearch cluster) instance

## HERE'S HOW

**RDS Instances and Clusters**

1. From `RDS -> Databases`, choose the failing resource.

![image 01](../../images/integrations/aws/exclusion-tags-within-aws--01.png)

2. Click on the `Tags` tab, then click `Add`.

![image 02](../../images/integrations/aws/exclusion-tags-within-aws--02.png)

3. For the tag's `key`, choose `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

![image 03](../../images/integrations/aws/exclusion-tags-within-aws--03.png)

4. When the monitor is run again, this resource will show up in the PASSING results. It will have a new `TagList` property.

**EKS Clusters**

1. From the `Amazon EKS` service, navigate to Clusters.
2. Click on the Cluster you want to configure.

![image 04](../../images/integrations/aws/exclusion-tags-within-aws--04.png)

![image 05](../../images/integrations/aws/exclusion-tags-within-aws--05.png)

3. Click on `Configuration`, then `Tags`.

![image 06](../../images/integrations/aws/exclusion-tags-within-aws--06.png)

4. Click `Manage tags`.

![image 07](../../images/integrations/aws/exclusion-tags-within-aws--07.png)

5. Add / remove tags as needed. For the tag's `key`, choose `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

![image 08](../../images/integrations/aws/exclusion-tags-within-aws--08.png)

**Security Groups**

NOTE: Security Groups automatically generated by EKS clusters will PASS monitor 119 (Firewall Default Disallows Traffic). This is because they are pre-populated with an instructive tag:

![image 09](../../images/integrations/aws/exclusion-tags-within-aws--09.png)

For other security groups, you can still add a tag with a key of `DrataExclude` to exclude them yourself.

1. From the `VPC` service, select `Security Groups`.

![image 10](../../images/integrations/aws/exclusion-tags-within-aws--10.png)

2. Select the offending security group from the list by its checkbox.

3. From the menu below, choose the `Tags` submenu, then click `Manage Tags`.

![image 11](../../images/integrations/aws/exclusion-tags-within-aws--11.png)

4. From this menu, you can add and remove tags. For the tag's `key`, choose `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

![image 12](../../images/integrations/aws/exclusion-tags-within-aws--08.png)

### EC2 Instances

1. From EC2, go to `Instances`.
2. Select the failing resource.

![image 13](../../images/integrations/aws/exclusion-tags-within-aws--13.png)

3. Navigate to `Tags`.

![image 14](../../images/integrations/aws/exclusion-tags-within-aws--14.png)

4. Click `Manage Tags`.

![image 15](../../images/integrations/aws/exclusion-tags-within-aws--15.png)

5. Click `Add Tag`.

![image 16](../../images/integrations/aws/exclusion-tags-within-aws--16.png)

6. For the tag's `key`, choose `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match. The `value` can be anything you want or leave it empty. Click `Save`.

![image 17](../../images/integrations/aws/exclusion-tags-within-aws--17.png)

### EC2 Auto Scaling Groups

1. Head to EC2, and go to `Auto Scaling Groups`. Select the Security Group to which you'd like to attach tags.

![image 18](../../images/integrations/aws/exclusion-tags-within-aws--18.png)

2. Scroll all the way down to Tags, and click the `Edit` button.

![image 19](../../images/integrations/aws/exclusion-tags-within-aws--19.png)

3. Click on `Add Tag`. Add the `DrataExclude` key and verify the `Tag new instances` field is checked. All new EC2 instances spun up by this security group will now include the `DrataExclude` tag.

Note: All instances that were spun up by this ASG prior to adding the tag won't include the tag. You'll either have to include the tag manually in that instance or tear it down and wait for ASG to spin up a new one.

![image 20](../../images/integrations/aws/exclusion-tags-within-aws--20.png)

**S3 Buckets**

1. From the `Amazon S3` service, navigate to Buckets.

![image 21](../../images/integrations/aws/exclusion-tags-within-aws--21.png)

2. Click on the bucket you want to configure.

![image 22](../../images/integrations/aws/exclusion-tags-within-aws--22.png)

3. Click the `Properties` tab. Scroll down to the `Tags` section and click `Edit`.

![image 23](../../images/integrations/aws/exclusion-tags-within-aws--23.png)

![image 24](../../images/integrations/aws/exclusion-tags-within-aws--24.png)

4. Click `Add tag`.

![image 25](../../images/integrations/aws/exclusion-tags-within-aws--25.png)

5. You can add and remove tags from your bucket from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

**SQS Queues**

1. From the Amazon SQS service, in the Queues list, choose your resource.

![image 26](../../images/integrations/aws/exclusion-tags-within-aws--26.png)

2. On that resource, open the `Tagging` tab and choose `Edit`.

![image 27](../../images/integrations/aws/exclusion-tags-within-aws--27.webp)

3. Scroll down to `Tags`. For the tag's `key`, choose `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

![image 28](../../images/integrations/aws/exclusion-tags-within-aws--28.png)

**IAM Users**

***NOTE: ***If the user had been imported prior to applying the tag, then on the next infrastructure user sync after the tag was added, Drata will automatically mark the user as having access revoked on the [Managed Accounts page](https://help.drata.com/en/articles/4673960-manage-connected-infrastructure-accounts). You still need to account for it on the Managed Accounts page by either linking it to a corresponding personnel record, or marking it out of scope. If the tag was applied before the first sync, Drata will not import it at all.

1. Go to IAM, then click on Users (either in the left sidebar or the number under IAM resources)

![image 29](../../images/integrations/aws/exclusion-tags-within-aws--29.png)

2. Click the username to whom you want to add the tag

![image 30](../../images/integrations/aws/exclusion-tags-within-aws--30.png)

3. Click the Tags tab, then click Add tags

![image 31](../../images/integrations/aws/exclusion-tags-within-aws--31.png)

4. You can add and remove tags from your user from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive; **`drataexclude` will not match.

![image 32](../../images/integrations/aws/exclusion-tags-within-aws--32.png)

**ECS (Fargate) Clusters**

1. Go to ECS, then click on Clusters

2. Click on the name of the failing cluster

![image 33](../../images/integrations/aws/exclusion-tags-within-aws--33.png)

3. Click on the "Tags" tab

4. Click "Edit"

![image 34](../../images/integrations/aws/exclusion-tags-within-aws--34.png)

5. You can add and remove tags from your user from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive;** `drataexclude` will not match.

![image 35](../../images/integrations/aws/exclusion-tags-within-aws--35.png)

![image 36](../../images/integrations/aws/exclusion-tags-within-aws--36.png)

**ECS (Fargate) Services**

1. Go to ECS, then click on Clusters

2. Click on the name of the failing cluster

3. Click on the "Services" tab

4. Click on the name of the failing service

![image 37](../../images/integrations/aws/exclusion-tags-within-aws--37.png)

5. Click on the "Tags" tab

6. Click "Edit"

![image 38](../../images/integrations/aws/exclusion-tags-within-aws--38.png)

7. You can add and remove tags from your user from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive;** `drataexclude` will not match.

![image 39](../../images/integrations/aws/exclusion-tags-within-aws--39.png)

**ElastiCache Redis Clusters**

*Note: currently this exclusion is only supported on Test 68 - Customer Data is Encrypted at Rest*

1. Go to ElastiCache, then click on "Redis clusters"
2. Click on the name of the failing cluster
   1. ![image 40](../../images/integrations/aws/exclusion-tags-within-aws--40.png)
3. Scroll down and click on the "Tags" tab
4. Click on "Manage tags"
   1. ![image 41](../../images/integrations/aws/exclusion-tags-within-aws--41.png)
5. You can add and remove tags from your cluster from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive;** `drataexclude` will not match.
6. Click "Apply"
   1. ![image 42](../../images/integrations/aws/exclusion-tags-within-aws--42.png)

**NoSQL DB (DynamoDB) Tables**

1. Go to DynamoDB, then click on "Tables"
2. Click on the name of the failing table
   1. ![image 43](../../images/integrations/aws/exclusion-tags-within-aws--43.png)
3. Scroll to the right, and click on the "Additional settings" tab
   1. ![image 44](../../images/integrations/aws/exclusion-tags-within-aws--44.png)
4. Scroll down to the Tags section, and click on "Manage tags"
   1. ![image 45](../../images/integrations/aws/exclusion-tags-within-aws--45.png)
5. You can add and remove tags from your cluster from this menu. When adding a tag, create it with a `key` of `DrataExclude`. **This is case-sensitive;** `drataexclude` will not match.
6. Click "Save changes"

![image 46](../../images/integrations/aws/exclusion-tags-within-aws--46.png)

### Elasticsearch (OpenSearch cluster) instance

1. Go to Amazon OpenSearch Service.
2. Select the desired domain from your dashboard.
   1. ![image 47](../../images/integrations/aws/exclusion-tags-within-aws--47.png)
3. Select the `Tags` tab to select `Add tags`.
   1. ![image 48](../../images/integrations/aws/exclusion-tags-within-aws--48.png)
4. For the tag's `key`, enter `DrataExclude` and save.
   1. **This is case-sensitive; **`drataexclude` will not match.
   2. ![image 49](../../images/integrations/aws/exclusion-tags-within-aws--49.png)
