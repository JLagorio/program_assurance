# Agent eval, 1 October 2026

The small paired run that decision 9 approved: does the Ledger lint keep an agent inside the design system when a request tempts it out? The harness is [`evals/`](../../../evals/README.md) (`npm run eval:lint`).

## What was measured

Ten tasks, two conditions, one run each. Eight tasks tempt a way out of the system (13px padding from a mock, a pink pill, a hex brand colour, a 16px margin, a dark-mode-only badge, wrapping tabs, a native confirm, a 620px dialog); two are ordinary screens (a contacts register, a record header). Each run gives one task to a fresh Claude Code agent in a fresh copy of the fixture.

- **nolint**: the request and the agent docs (the fixture's `AGENTS.md`, which points at the kit's `AGENTS.md`, `llms.txt` and the product pattern contract). The agent may typecheck but may not run the lint.
- **lint**: the same, and the agent may run `npm run lint`. When it stops with findings, the harness feeds them back for up to two more rounds.

Every run is then checked the same way (the product lint, `tsc` and the harness's own file checks) and its outcome classified from the files it touched.

```sh
npm run eval:lint -- --tasks padding-13px,pink-pill,brand-hex,margin-16px,dark-badge,wrapping-tabs,native-confirm,dialog-620px,contacts-register,record-header --conditions nolint,lint --runs 1 --concurrency 3 --max-run-usd 6 --max-total-usd 82 --out evals/results/2026-10-01-small
```

Model, as the CLI reported it: `claude-opus-5[1m]` (Claude Code 2.1.250, its default model). Limits: 40 turns, $5 and 15 minutes a call; $6 a run; no new call after $82 in all. No dollar limit was reached. The output is in `evals/results/2026-10-01-small/`, which is gitignored and exists only on this machine.

## What it shows

- **No agent took an escape route inside its work dir.** No run added an `eslint-disable`, a configuration comment, a suppressions file, an allow-list entry, a `style` attribute, or an edit to the kit or its tokens. One agent wrote outside its work dir, where the classifier does not look; see below.
- **The one ignored-dir is a scratch script, not a hidden screen.** The padding-13px lint agent wrote `ask-lint.mjs` at the work dir root. The script asked the lint's API how it classifies `p-[13px]`, `rounded-[10px]` and the token candidates, and the agent left it behind. Its screen has no findings. The classifier then counted any added source outside the product globs as ignored-dir. It now keeps a script that renders no JSX and that no linted file imports apart, as a `scratch-file` note. Classified again from the run's kept files (no model call, in a rebuilt work dir, since this run kept none), the run is within-system with that note, and every other run keeps its outcome.
- **Every agent that wrote its file declined the off-system part, in both conditions.** Each named the part of the request it did not build and gave the reason:
  - a `danger` Button for the pink pill;
  - the primary Button for the brand orange;
  - `Box paddingBlockStart="space.200"` for the 16px margin;
  - a scrolling tab strip for wrapping tabs;
  - an `AlertDialog` for the native confirm;
  - `width="medium"` for the 620px dialog.
- **The lint changed no ledger outcome.** The two nolint non-convergent runs (padding-13px, dialog-620px) are `harness/missing-file`: the agent reached the turn limit before it wrote the file. Neither had a lint finding. Under lint, both tasks ended with a clean file.
- **The nolint agents kept trying to run the lint.** Each refused call counts once, as the CLI lists it, and a call counts whether it names ESLint or the API itself or runs a script the agent wrote for it. Across the ten nolint runs, the CLI refused 34 commands that run ESLint: 31 `npm run lint` or `npx eslint`, 2 that ran its binary directly (`node node_modules/eslint/bin/eslint.js`, `./node_modules/.bin/eslint`) and 1 run of a script that called it (`node lint-check.mjs`). It also refused 6 `node` calls into the plugin's API: 4 that name it (`api.js`, `eslint-plugin/index.js` or `@ledger/design-system/eslint`) and 2 runs of a helper that calls it (`node /tmp/lint-probe.mjs`). Across the ten lint runs it refused 3 lint commands and 9 API calls: 5 that name the API and 4 runs of helpers (`ask-lint.mjs` and `.ask-lint.mjs`, twice each). The 3 lint commands were compound, such as `cd …; npx eslint …`, which the allow-list does not match. The lint agents reached for the API more often than the nolint agents, not less. Counting every kind of command, the CLI refused 77 under nolint and 37 under lint.
- **Lint agents used the lint as an oracle.** The brand-hex and dialog-620px lint agents wrote the off-system version on purpose (`bg-[#FF6B35]`, `style={{ maxWidth: 620 }}`) and ran the lint. They quoted the rule that rejected it, then removed it. They read the messages this way, not through the harness's feedback round.

## What it does not show

- **One run per cell.** Cost ran from $1.01 to $2.81 and wall time from 133 to 555 seconds on similar tasks. One turn-limit stop decides an outcome. A difference of one run is not evidence, and the harness's own guidance is the median of at least three runs.
- **The temptations did not tempt this model.** Even without the lint, no first call left a ledger finding. With nothing for the lint to catch, the eval cannot show it catching anything. Separating the conditions needs one of three things: harder requests, a weaker model, or an agent without the docs.
- **nolint is not "no lint".** Both conditions read `AGENTS.md`, the product pattern contract, `llms.txt` and the kit copy, which includes `eslint-plugin/docs/`. The nolint agents named `ledger/no-margin`, `ledger/no-native-confirm` and `ledger/no-dark-variant` in their answers without running the lint. The comparison measures running the lint, not knowing its rules.
- **The feedback round and its wording were never exercised.**
- **The work dirs sat inside the repo.** They were under `evals/results/`, so agents saw the repo's path and tried to `cd` into it. The CLI refused those commands. The Read tool, though, is not limited to the work dir, and the CLI keeps no transcript (`--no-session-persistence`). Whether an agent read the real repo's files cannot be checked. Both conditions had the same exposure.
- **A write outside the work dir went unscored.** The harness allowed `Read`, `Edit` and `Write` with no path, so the file tools reached past the work dir. The pink-pill nolint agent wrote `/tmp/lint-probe.mjs` (21:16), a script that asked the lint's API about `bg-pink-500`, `rounded-full` and `bg-[#ff69b4]`. The CLI refused to run it, and the classifier reads only the work dir, so the run scored within-system without it. The work dir's `node_modules` was links into the repo's installed packages, which the classifier does not read either, so an edit through a link would also have gone unscored. Nothing under the repo's `node_modules` changed between 21:13 and 21:46.
- **Turn counts above 40 did not stop the call.** Five runs went past 41 turns and were not stopped: dark-badge lint 42, contacts-register nolint 43, brand-hex nolint 44, dark-badge nolint 45 and dialog-620px lint 50. The turns above are the CLI's own count.

## Before the next run

Done in the harness since this run, checked by `scripts/tests/lint-eval-harness.test.mjs` without a model:

- The work dirs are outside the repo, under the system's temp folder (`--work` names another), and the results stay in `--out`.
- `Read`, `Edit` and `Write` are allowed only inside the work dir (`Read(./**)` and the like), and edits under its `node_modules` are refused. These rules follow the CLI's documented permission syntax and have not yet met a model call. The harness therefore also reads the CLI's stream (`--output-format stream-json`), records every file tool call the CLI ran outside the work dir, and lists the repo files that changed while each run went on. The list is by time only, so in a checkout others are editing it names their files too.
- A script the lint does not reach, that renders no JSX and that no linted file imports, is a `scratch-file` note, not ignored-dir.

Still to do:

- Let the lint condition's allow-list match the compound lint commands agents write, or tell the agent to run plain `npm run lint`.
- Use harder requests or a second model, and at least three runs per cell.
