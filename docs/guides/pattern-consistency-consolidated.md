Josef clarified that the outer preview header is global navigation only. The previous follow-up incorrectly moved the record name and domain actions into that bar. **Audit conclusion — before implementation**

The application has a strong component library but an incomplete product workflow contract. Shared application wrappers distribute inconsistent headers, row actions, record previews, and forms. Guidance disagrees, and checks do not reliably cover either those workflows or all the application code that implements them.

Claude's most valuable addition is the broader inventory: form footers, native confirmations, inline previews, record layouts, loading/empty states, browser titles, and the shared files through which changes will reach many screens. Codex contributes representative browser evidence, behavioral defects, and enforcement checks. Claude's report already incorporates several Codex findings; that repetition is not independent verification.

**Feedback on the proposed contract: retain the intent, narrow the rules**

1. **Forms:** choose one default for comparable product create/edit tasks, with named exceptions for the program wizard, inline editing, selection/linking, and contextual draft editing. Do not convert the wizard's Sheet solely because another tree uses a Dialog: the wizard updates its parent draft, whereas the product-element editor owns a local draft. Normalize recovery behavior first. Current [Forms guidance](../../packages/design-system/src/stories/patterns/Forms.mdx:80) explicitly permits multiple surfaces.
2. **Headers:** enforce correct grouping and one page-level h1 in the rendered page. Do not equate “one per route” or “none inside TabsContent” with heading correctness; nested route components and composed children cross file boundaries. Existing div wrappers were explicitly retained by the [layout migration](../../docs/guides/layout-composability-audit.md:39). Use PageHeader.Heading for new standard compositions without treating every working wrapper as broken.
3. **Descriptions:** Claude correctly found the historical [September 5 sweep](../../docs/next.md:87), which my first audit did not account for. But current [PageHeader guidance](../../packages/design-system/src/stories/layout/PageHeader.mdx:15) permits descriptions. The combined finding is conflicting policy, not simply “missing descriptions” or “all descriptions prohibited.” Retain the generic component; define product copy rules explicitly.
4. **Navigation:** text that navigates must be a real anchor; actions use buttons, as [TextLink already documents](../../packages/design-system/src/stories/components/TextLink.mdx:9). Allow custom components that render anchors and forward props/refs. Do not invent fake destinations to satisfy a JSX rule. When a friendly full-record route is missing, specify that capability and its fallback explicitly.
5. **Preview ownership:** centralize the collection preview in an application composition. Keep displayed row order, destinations, and availability out of Shell; [Shell's contract](../../packages/design-system/src/stories/layout/Shell.mdx:24) assigns them to the route.
