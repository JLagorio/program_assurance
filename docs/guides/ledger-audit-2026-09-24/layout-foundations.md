# Family deep dive: navigation, shell, page layout, primitives and tokens

Part of the [Ledger audit, 24 September 2026](README.md).

Six units: navigation and scrolling (NAV), the Shell's root and side nav (SHA), its top nav, panel and splitter (SHB), page layout (PGL), the primitives (PRM) and the tokens (TOK). Five problems cross the units and are cheapest fixed once:

- The parts that own focus clip it, leave it behind or drop it: NAV-1 and NAV-4 (clipped rings), SHA-1 and SHA-3 (the phone overlay), SHB-1 and SHB-2 (the panel), PGL-11 (route changes).
- `forced-colors.css` covers four families. One pass over it, with the forced-colours test project widened, closes TOK-1, TOK-4, SHA-5, SHB-8, NAV-13 and PGL-7 here, and BTN-8, SEL-2, DAT-6 and MOD-9 in the other sections (A11-2 in the cross-cutting section).
- State is shown only by a fill of about 1.1:1: SHA-5, TOK-7, and BTN-2 in actions and inputs.
- Heading levels and title styles are fixed per part, so previews and sheets copy class strings and their outlines flatten: PGL-1, PGL-3, PRM-1, PRM-2.
- Remembered widths and caps: the side nav and panel caps ignore each other (SHA-2, SHB-4), and `defaultWidth` is stored as if the reader chose it (SHB-3, SHA-13).

Four issues were found in more than one unit and are written up once: the record trail (NAV-2 with NAV-9, NAV-10 and PGL-10), the width caps (SHA-2, SHB-4), the search-failure alert (SHA-10, SHB-11) and the Profile name (SHA-14, SHB-13, SHB-14).

## Breadcrumb, Scroller, ScrollArea, Resizable

The parts are well built, but the scroll parts leave focus visibility and focusability to their callers, and the prototype shows it. Confirmed live: a horizontal ScrollerViewport clips focus rings, so the saved-views control on every register shows no focus, and ScrollArea's root clips its own ring. The worst app defect is the record trail: TanStack's prefix matching marks ancestors as the current page, and the focused program views add a second current page. Fix the two clipped rings first with the existing `outline-field-focused` inset utility, then add one app trail adapter. Resizable's defects are real, but no product uses it yet.

Keep: Breadcrumb folds to its container in one pass that cannot oscillate (middle levels first, names only down to an 80px floor, and a folded router link still navigates on the client); a named nav landmark, an ordered list, hidden separators, `aria-current` on the page and a real menu button for folded levels; exhaustive Breadcrumb play tests for one line, line-end separators, fold order, menu contents and render-prop merging; Scroller arrows only when the viewport overflows, at an edge that can still scroll and where the pointer can hover, as labelled buttons out of the tab order that follow the computed direction and reduced motion; focused items scroll into view without scrolling the page, and a nested Scroller does not scroll again; ScrollArea's viewport is a tab stop only while it overflows, with keyboard scrolling and direction from LedgerProvider; Resizable's separator semantics, Home/End/F6, a visible ring on the 1px rule and tested keyboard resizing and persistence; overscroll containment only on popup lists.

**NAV-1 · A horizontal ScrollerViewport clips focus rings, so every register's saved-views control shows no focus** (high)
[scroller.tsx:315-335](../../../packages/design-system/src/components/scroller.tsx#L315-L335), [toolbar.tsx:298-299](../../../packages/design-system/src/patterns/toolbar.tsx#L298-L299), [filter.tsx:439-440](../../../packages/design-system/src/patterns/data-table/filter.tsx#L439-L440)
The horizontal viewport is `overflow-x-auto overflow-y-hidden` and leaves no room for an outline. Toolbar's views strip and the DataTable presets strip compose it with no padding, and the Scroller's own Horizontal story adds `py-050` by hand to get around it. On /programs at 1280px the focused "All programs 7" button (y 106–134) exactly fills the viewport (106–134), so its 2px ring at a 2px offset is clipped on every side; /work and /risks are the same. Keyboard users cannot see focus on the saved views of any register (2.4.7).
Fix:

- Keep rings visible in ScrollerViewport itself: give descendants the inset ring through the existing `outline-field-focused` utility ([utilities.css:996](../../../packages/design-system/src/generated/utilities.css#L996)), or give the viewport block and inline padding in tokens, with no margins. Inline padding is needed too, because the first and last items clip on that axis.
- Add a play assertion that a focused item's outline fits inside the viewport's clip rect, covering the views and presets strips.

**NAV-2, NAV-9, NAV-10, PGL-10 · Record trails mark ancestors, and a second program crumb, as the current page** (high)
[breadcrumb.tsx:518-551](../../../packages/design-system/src/components/breadcrumb.tsx#L518-L551), [Breadcrumb.mdx:160-184](../../../packages/design-system/src/stories/components/Breadcrumb.mdx#L160-L184), [program-workspace.tsx:169-181](../../../src/components/prototype/program-workspace.tsx#L169-L181), [program-record.tsx:103-120](../../../src/components/prototype/program-record.tsx#L103-L120), [requirement-record.tsx:459-466](../../../src/components/prototype/requirement-record.tsx#L459-L466), [tasks.$taskId.tsx:106-120](../../../src/routes/tasks.$taskId.tsx#L106-L120), [campaigns.$campaignId.tsx:58-80](../../../src/routes/campaigns.$campaignId.tsx#L58-L80), [record-browser.tsx:980-1003](../../../src/components/app/record-browser.tsx#L980-L1003)
BreadcrumbLink passes `render={<Link />}` straight to TanStack Link, which matches by path prefix and applies `aria-current="page"` after any props the kit passes. On /programs/<WS-X90>/sctm three items carry `aria-current=page`: the Programs link, the program and the view. The program is a second BreadcrumbPage because program-workspace renders it that way whenever a focused view is set (eight routes), so the trail cannot go back to the program. The trails are composed by hand at 19 sites in 15 files. None sets exact matching, and five show the placeholder "Program" as link text while loading. Screen-reader users hear "current page" on parent levels on almost every record page (1.3.1, 4.1.2).
Fix:

- App: one adapter in `src/components/app`, for example `RecordTrail levels={[…]} page={title}`. It renders BreadcrumbLink over TanStack Link with `activeOptions={{ exact: true, includeSearch: false }}`, the separators and one final BreadcrumbPage, and shows Absent or a skeleton while a level loads. The program becomes a link to `/programs/$programId` when a view follows it. Migrate the 19 sites (PGL-10 counted 21) and name the adapter in product-patterns.md Record pages.
- Kit: under Router link composition, add a paragraph and a Dont specimen saying that ancestor links use exact matching or render no active state. Warn in development when a list has more than one BreadcrumbPage, or a BreadcrumbPage that is not last. Do not strip `aria-current` after render, because React and TanStack own that attribute.

**NAV-4 · ScrollArea's own focus ring is clipped by its root** (medium)
[scroll-area.tsx:18-29](../../../packages/design-system/src/components/scroll-area.tsx#L18-L29)
The root is `overflow-hidden`, and the viewport draws `outline-focused` 2px outside a box that fills the root, so the root clips all of it. On ScrollArea Vertical, Tab focuses the viewport and PageDown scrolls it 208px, but no ring shows. Choosing.mdx recommends ScrollArea for a visible bar, so every new composition inherits this (2.4.7).
Fix: replace `focus-visible:outline-focused` with `focus-visible:outline-field-focused`, as in NAV-1, and assert in a play function that the ring is visible (a negative outline offset, or a pixel check).

**NAV-5 · Stepper and Timeline strips are unnamed tab stops because ScrollerViewport does not manage focusability** (medium)
[scroller.tsx:307-330](../../../packages/design-system/src/components/scroller.tsx#L307-L330), [stepper.tsx:90-93](../../../packages/design-system/src/components/stepper.tsx#L90-L93), [timeline.tsx:141-144](../../../packages/design-system/src/components/timeline.tsx#L141-L144), [program-timeline.tsx:78-84](../../../src/components/prototype/program-timeline.tsx#L78-L84)
ScrollerViewport knows whether it overflows but leaves tabIndex, role and name to the caller. Stepper and Timeline hard-code `tabIndex={0}` with no role or label. At 1400px every horizontal viewport in the Timeline and Stepper matrices is a tab stop with no role, no name and no overflow, and the Timeline ones hold nothing focusable. The program timeline wraps this in its own `role=region tabIndex=0` scroller, so the rail has two nested tab stops, one of them unnamed.
Fix:

- ScrollerViewport sets tabIndex 0 only while it overflows and has no focusable descendant (unless the caller sets it), adds `role="region"` and requires `aria-label` whenever it is focusable, and warns in development when a focusable viewport has no name.
- Drop the hard-coded tabIndex in Stepper and Timeline, and remove the prototype's outer scroller.

**NAV-6 · Resizable arrow keys work backwards in right-to-left layouts** (medium)

## Shell root, side nav, overlay and storage

Shell A is carefully built: named landmarks, locale default names, inert closing content, interruptible motion, reduced motion and a pre-paint script, and the 18 September bug where a phone reload overwrote the saved widths is fixed. Its weakness is the phone overlay. Checked live, it looks modal but leaves focus on the toggle it covers, lets Tab reach five covered controls and makes nothing inert. Choosing a destination neither closes it nor moves focus, so the prototype hand-builds that and the schema inspector stays covered after navigating. Fix SHA-1 and SHA-3 together on Base UI's modal focus management; the current-page indicator comes next.

Keep: named landmarks everywhere ("Top navigation", "Side navigation", "Main content", complementary Aside and Panel), all locale messages with a label override; the closing overlay and scrim become inert and aria-hidden at once, and a reversed animation resumes from the rendered frame; reduced motion in the overlay, the rail width and the panel grid; the pre-paint `shellScript` with validated storage, so phone reloads no longer overwrite desktop widths (PersistedWidths covers it); the icon rail keeps visually hidden labels as names, shows tooltips on hover and focus, keeps the mark in place and returns focus to the toggle; the splitter's APG window-splitter pattern with RTL-correct arrows and pointer deltas; dense play functions (Desktop, RTL, WidthMotion, Mobile390, first paint, Shortcut, Skip links, Remembered).

**SHA-1 · The phone side-nav overlay looks modal but does not take or hold focus, leaves the page reachable and covers its own toggle** (high)
[root.tsx:124-128](../../../packages/design-system/src/layout/shell/root.tsx#L124-L128), [side-nav.tsx:122-167](../../../packages/design-system/src/layout/shell/side-nav.tsx#L122-L167), [shell.css:20-24](../../../packages/design-system/src/styles/shell.css#L20-L24), [:211-219](../../../packages/design-system/src/styles/shell.css#L211-L219)
`openSideNav` only sets state. The scrim is a focusable full-screen button, the nav has no dialog role, and nothing makes Main or TopNav inert. The overlay sits at z 50 over the top nav (z 30), so it covers the toggle that opened it. On Shell Frame at 390×844, after Enter on the toggle, focus stays on the now-covered toggle. Tab 1–5 land on Switch product, Equinox home, Search, Create and More, all under the nav or the scrim; Tab 6 is the scrim and only Tab 7 reaches "My queue". Keyboard users land on controls they cannot see (2.4.11, 2.4.3), screen-reader users can swipe into the page behind, and there is no visible close.
Fix:

- Build it on Base UI's modal focus management (a Dialog or Drawer popup, or FloatingFocusManager with `modal`, which already hides outside content), not a hand-rolled trap.
- On open, focus the current item or the first link. Make the rest of the Shell inert. Add a visible Close inside the nav, or keep the top nav and its toggle above the overlay. Make the scrim aria-hidden with tabIndex -1.
- Extend Mobile390 to assert that Tab after opening stays inside the nav.

**SHA-3 · The kit does not close the phone overlay or move focus when a destination is chosen** (high)
[root.tsx:114-123](../../../packages/design-system/src/layout/shell/root.tsx#L114-L123), [side-nav.tsx:262-312](../../../packages/design-system/src/layout/shell/side-nav.tsx#L262-L312), [shell.tsx:295-311](../../../src/components/app/shell.tsx#L295-L311), [schema-shell.tsx:83-106](../../../src/components/app/schema-shell.tsx#L83-L106)
`closeSideNav` returns focus only for the Escape and scrim triggers, and SideNav.Item never closes the overlay. The prototype's RouteNavigation closes it on a pathname change behind a hard-coded `matchMedia('(min-width: 64rem)')`, while the kit reads `dimension.breakpoint.lg`, and then focuses `main`. SchemaLayout has nothing: at /schema at 390px, tapping Scopes goes to /records/scopes with the overlay still open and focus still on the link. Any product that calls `useSideNav().collapse()` from inside the overlay drops focus to the body, because the nav turns inert while closing.
Fix:

- Close the overlay when a SideNav.Item or any link inside it is activated below the desktop breakpoint, and move focus to Main, with an opt-out.
- Expose the current mode, for example `useSideNav().isOverlay` or `screen`, so products stop duplicating media queries. Then delete RouteNavigation from the app shell; PGL-11 covers the desktop half of route-change focus.

**SHA-2, SHB-4 · The side nav and the panel are each capped at half the viewport, so together they can shrink Main to its padding** (medium)
[splitter.tsx:12-14](../../../packages/design-system/src/layout/shell/splitter.tsx#L12-L14), [root.tsx:90-93](../../../packages/design-system/src/layout/shell/root.tsx#L90-L93), [shell.css:73](../../../packages/design-system/src/styles/shell.css#L73), [:173-177](../../../packages/design-system/src/styles/shell.css#L173-L177), [Shell.stories.tsx:1623-1640](../../../packages/design-system/src/stories/layout/Shell.stories.tsx#L1623-L1640)
`clampWidth` caps each area at `innerWidth / 2` without looking at the other, and the CSS caps each at `50vw`. At 1440px, with the nav expanded, the panel open and End pressed on both splitters, the result is a 720px nav, a 720px panel and a 48px Main; at 1280px it is 640/48/640. The page content is gone, and the top nav's Create button and end icons are painted over the panel title. The PersistedWidths story asserts 720/720 as correct, and with `persist` the layout comes back on every reload, against Shell.mdx's promise that the panel "covers nothing".
Fix:

- Cap each area at the viewport minus the other areas minus a Main minimum from a new `dimension.layout` token (about 360–480px), in both `clampWidth` (so `aria-valuemax` is truthful) and the CSS `min()` expressions. Atlassian caps the panel at 50% of the content area, which is the same idea.
- Give TopNav.Middle and TopNav.End `min-w-0` or clipping, so the top nav cannot paint into the panel column.
- Make PersistedWidths assert Main's minimum instead of 720/720.

**SHA-4 · "Skip to Side navigation" does nothing while the side nav is hidden** (medium)
[root.tsx:328-350](../../../packages/design-system/src/layout/shell/root.tsx#L328-L350), [side-nav.tsx:104](../../../packages/design-system/src/layout/shell/side-nav.tsx#L104), [shell.css:349-354](../../../packages/design-system/src/styles/shell.css#L349-L354)

Below lg the nav is `display: none` until the overlay opens, and so it is in desktop `hidden` collapse, where `getElementById(id)?.focus()` does nothing. shell.css already hides the Main skip link when the panel replaces Main, but the nav has no such rule. The first control a keyboard user reaches is broken.
Fix: register or show the nav skip link only while the nav is inline or in the rail, or, below lg, make it open the overlay and focus the nav.

**SHA-5 · The current destination is barely visible, looks the same as hover and disappears in forced colours** (medium)
[side-nav.tsx:252-255](../../../packages/design-system/src/layout/shell/side-nav.tsx#L252-L255), [:289](../../../packages/design-system/src/layout/shell/side-nav.tsx#L289), [shell.css:291-298](../../../packages/design-system/src/styles/shell.css#L291-L298), [forced-colors.css](../../../packages/design-system/src/styles/forced-colors.css)

**SHA-6 · SideNav.Expandable has no current-page state, so the rail loses a nested current page and its badges** (medium)
[side-nav.tsx:314-407](../../../packages/design-system/src/layout/shell/side-nav.tsx#L314-L407), [shell.css:321-327](../../../packages/design-system/src/styles/shell.css#L321-L327)

**SHA-7 · onExpand and onCollapse mix up desktop collapse with the phone overlay and report the wrong trigger** (medium)
[root.tsx:34](../../../packages/design-system/src/layout/shell/root.tsx#L34), [:114-128](../../../packages/design-system/src/layout/shell/root.tsx#L114-L128), [context.tsx:42-43](../../../packages/design-system/src/layout/shell/context.tsx#L42-L43)
On a phone, opening always reports `trigger: 'toggle-button'`, even from the shortcut or the hook, and closing fires `onCollapse` even when the overlay was already closed; the prototype calls `collapse()` on every phone route change. `'viewport'` is in the trigger type but never emitted. Fix: pass `{ trigger, screen: 'desktop' | 'overlay' }`, report the real trigger, fire only on real state changes, and either emit `'viewport'` or remove it from the type.

**SHA-10, SHB-11 · The app's search-failure alert is a stray grid child of Shell, hidden behind the modal palette** (medium)
[shell.tsx:244-250](../../../src/components/app/shell.tsx#L244-L250)

- Add to Shell.mdx that the root's children are its areas, and anything else must portal.

## Shell top nav, Panel and splitter

Shell B is solidly built: named landmarks, portal-based route contributions, container-aware panel headers and RTL-correct splitters. Its weak point is the panel's keyboard and focus contract, confirmed live. On desktop, opening a preview leaves focus on the eye, 65 Tab presses from the panel. Close returns focus to a stale row once the reader has used another eye, and Escape in an embedded search closes the whole system preview. Fix focus on open at every width with `initialFocus` and `finalFocus`, then Escape that ignores editable targets, then the widths (SHB-3, SHB-5 and the caps in SHA-2). Replacing the register between 1024 and 1279px is the documented design and needs a decision, not a bug fix.

Keep: every area is a named landmark with a skip link and locale default names; route-owned Aside and Panel go through stable portals, so route context and state travel with them and unmounting closes them; the panel header responds to its own width (title on its own row below 400px), with play tests at 240, 320 and 640px; the splitter's separator role, valuenow/min/max, valuetext, arrows, Home and End; the 18 September RTL fix holds for pointer and keys on both edges; the coarse-pointer hit band, pan-y gesture separation and pointercancel restore; remembered widths are stored apart from viewport caps and applied before paint; Escape inside a Base UI menu or dialog in the panel stays contained; Panel parts forward props, ref and render, and the Composed story shows the heading-level and label overrides; thorough play functions for banner offset, skip links, the shortcut, persisted widths and RTL splitters.

## Box, Stack, Inline, Flex, Grid, Bleed, Text, Heading

The layout primitives are principled: tokens only, no margins, Bleed as the one negative margin, and no links or buttons in the `as` unions. The problem is the typography half. Heading's ramp and roles contradict the titles the kit ships, so nothing uses Heading, and Text is bypassed about 190 times because it cannot preserve line breaks, break long words or set tabular numerals. The layout weak spots are narrower: `grow="fill"` has no zero minimum size, Stack's stretch default turns ten Buttons into full-width bars, `maxLines={1}` fails on the default span, and the fieldset and form entries in `as` cannot take their own props. Settle the ramp first (a design call), then add level overrides, then lint the primitives' own className. Two candidate findings, a viewport grid in a dialog and a Flex deprecation, did not hold.

Keep: token-typed props that compile to literal classes, so an invalid space or colour is a type error; no margin props, with Bleed the one sanctioned negative margin; the element unions exclude `a` and `button`, so primitives cannot fake controls; logical padding edges that are correct in RTL; a bold fill paints inverse text on its own, and a surface publishes itself for sticky children; Heading separates size from level, and size is required; Grid's responsive template passes through CSS variables, with a play test inside a panel; Inline separators are aria-hidden, dropped on lists and keep child keys; thorough MDX pages with Not built, Content, Accessibility and Don't sections; reversed directions are refused, so visual order stays DOM order.

## Tokens, colour mode, density and global styles

The token layer is sound: every semantic colour has a dark value, the contrast test composes alpha correctly, `modeScript` prevents a flash, and the prototype has no hand-written colours. The defects sit at the edges the tests skip. Forced-colours support covers four families, so menus and lists lose their keyboard highlight, and buttons, dialogs, pressed toggles and selected rows lose their edges. The most urgent fix is one line in the app: src/styles.css imports the unused shadcn reference theme, which redefines Tailwind's `data-*` variants for the whole app build. Beyond those, tables lose tabular numerals, 13px fields zoom the page on iOS, and Dialog has no width scale.

Keep: every `color.*` and `elevation.*` token has a dark value; contrast.test composes translucent fills over their actual parent surfaces and checks hovered and pressed states in both modes; `modeScript` runs before first paint, with a three-state switch defaulting to System and storage in try/catch; the focus ring is an outline token that survives forced colours, used consistently; every animation utility has a reduced-motion override, and motion tokens are named by purpose; breakpoint tokens feed CSS, matchMedia and variants from one source; density is scoped to a table frame, not the document; the prototype has no hex colours, `dark:` variants or arbitrary classes; the DTCG and Figma exports are generated and drift-tested.

**TOK-2 · The app's shadcn reference CSS redefines Tailwind's `data-*` variants, so the chosen Select or Combobox option loses its fill** (high)
[styles.css:7](../../../src/styles.css#L7), [theme.css:20](../../../src/components/ui/theme.css#L20), [menu.ts:16-17](../../../packages/design-system/src/components/menu.ts#L16-L17), [button-group.tsx:66](../../../packages/design-system/src/components/button-group.tsx#L66)
src/styles.css imports the look-only shadcn reference theme, which imports `shadcn/tailwind.css`. That file declares custom variants for `data-open`, `data-closed`, `data-checked`, `data-unchecked`, `data-selected`, `data-disabled`, `data-active`, `data-horizontal` and `data-vertical`, and they apply to every class in the app, the kit's included. `data-selected` becomes `:where([data-selected="true"])`, but Base UI renders `data-selected=""`: in the app the rule is `.data-selected\:bg-selected:where([data-selected="true"])`, in Storybook `[data-selected]`. In Portfolio's "20 per page" Select the chosen option shows only the highlight tint and a checkmark. The prototype is the kit's test vehicle, yet it renders kit states differently from Storybook.
Fix:

- Remove the theme.css import from src/styles.css; nothing depends on it.
- In the kit, replace ButtonGroupSeparator's `data-horizontal:` and `data-vertical:` with `data-[orientation=horizontal]:` and `data-[orientation=vertical]:`.
- In test:app, fail if the app stylesheet redefines a variant the kit uses, or assert the compiled `data-selected` rule.
